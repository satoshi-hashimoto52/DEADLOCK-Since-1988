# スキン変更の基盤（最小実装・テスト用画面）（2026-10-21）

仕様：GitHub Issue #1「[仕様] スキン変更基盤・プレイヤー立ち絵・武器全体図・拡張装備のレイヤー設計」の開発順序2〜4の初期実装。
対象は既存のライフル腰だめ・ADS・ナイフ待機の3画像。新しいイラストは使っていない（既存画像の色替えのみ）。
色違いの配色は**試作用の暫定値**で、正式なデザイン・採用ではない。

## 仕組み

| 部分 | 内容 |
| --- | --- |
| 領域マップ | 表示画像と同じキャンバスの8bitグレー画像。画素値＝領域番号×32（0＝色を変えない）。1 武器本体、2 グローブ、3 手のひらの補強（現状どの画像にもなし）、4 手首の帯、5 袖の地色、6 袖の迷彩。左右の手は同じ番号（プレイヤースキンは両手共通） |
| 作成 | `Tools/pixelart/make_skin_regions.py 定義.json`：既存の部位分離（`split_layers.py`）の手のマスクと、新しく作る武器本体マスクから合成。原画・表示画像・レイヤー・手のマスクは読むだけ |
| 武器本体マスク | ライフル腰だめ・ADSのみ新規作成（`Masks/rifle_{hip,ads}_weapon_body.png`）。タン色の外装（ハンドガード・機関部・弾倉受け・銃床）だけ。黒・灰色の鉄部、照準器、赤い切り替え表示、線の黒は含めない。ナイフ本体のマスクは作っていない（ナイフの武器スキンは未対応） |
| 色替え | 領域ごとに、描かれた明るさ（HLSの明度＝陰影・ハイライト）を保ち、色相・彩度だけを置き換える（`recolor_preview.py` と同じ方式）。線の黒と領域0は元の色のまま |
| 描画 | シェーダー `Deadlock/Skinned Sprite`（URPの Sprite-Unlit-Default に色替えを追加）。領域マップと色の表は描画単位のプロパティで渡す。CPUでの画像の作り直しや画像の複製はしない |
| データ | `Assets/Game/Data/Skins/SkinCatalog.asset`：武器ID（`proto_rifle` など）ごとの武器スキンと、全武器共通のプレイヤー（手・腕）スキン。「標準」は常に選べ、一覧には書かない。武器スキンは武器の領域だけ、プレイヤースキンは手・腕の領域だけに効く（データ上も混ざらない） |
| 保存 | `SkinSelection`（端末内の PlayerPrefs、操作設定と同じ方式）。キー：`deadlock.skins.player`、`deadlock.skins.weapon.<武器ID>`。保存がなければ標準。存在しないスキンIDが保存されていても標準で表示 |
| 画面 | メニュー → 設定 → 「スキン（テスト用）」：ライフルの色、手・腕の色を別々に選ぶ。「すべて標準に戻す」。ナイフは「標準のみ（本体の色替えは未対応）」と表示。本番の装備画面ではない |

ナイフ攻撃の未完成ポーズは、ポーズ画像ごとに同じキャンバスの領域マップを作れば、同じ仕組み（`SpriteSkin.Apply`）で表示中のポーズに色を付けられる。

| --- | --- | --- |
