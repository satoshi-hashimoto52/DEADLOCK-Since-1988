### ライフルから再利用できる仕組み

コードを変えずに、データの追加だけで使えるもの：
- 腰だめ・ADSの取り込み：`WeaponArtDefinition`・配置ファイル・`PixelWeaponArt`。元画像は保持し、アルファを2値にした派生（`make_opaque.py`）を表示する。
- 腰だめ・ADSの動き：`WeaponViewProfile` を複製して調整する。反動・揺れ・リロードの下げと傾き・持ち替え・ADSへの移行。
- 部位の分割と領域マップ：`split_layers.py` → `make_skin_regions.py`、`verify_layers.py`・`review_layers.py`。武器の外装のマスクは定義の `weaponMasks`。
- 色替えの表示：`SkinnedSprite`、`SpriteSkin`。手・腕のスキンは武器を持ち替えても共通。
- 全体図の領域マップ：`make_image_regions.py`。

SMG専用に必要な作業：
- 素材：腰だめ（候補あり）、ADS、装備画面用の全体図。
- 腰だめ・ADSの配置ファイル。銃口・持つ位置・狙点は実画像から読み取る。
- 性能の定義（値はユーザーが決める）。
- 部位分割の定義：手の範囲、帯の指定、外装の色の規則。
- 武器スキンの試作色。
- **ゲームでSMGを持たせる方法**。今は銃が1丁だけなので、確認用の一時的な切り替えか、武器の選択（装備画面・プリセット）の実装が要る（コードの変更）。
- 装備画面の全体図をライフル以外にも設定できるようにする（コードの変更）。

### ゲームの配置での確認が必要なこと

ライフル腰だめの配置値をそのまま当てはめたプレビューを、ゲームの外で作った（`placement_preview_*.jpg`）。

- 当てはめた値：画面の高さ1045px、下へ0.05、横長の画面では右端に追従、4:3では位置を保つ。
- ゲームの表示処理での描画ではない。背景は射撃場の撮影画像。
- プレビューで分かったこと：
  - 3画面比とも、銃は画面の右下に収まり、画面中央（照準）をふさがない。
  - 袖の切り口は、待機でもリロードの中間でも画面の外。iPhone 16 Pro比で65〜92px、16:9で58〜82px、4:3で82〜171px外にある。持つ位置の仮定は2通り（ライフルの値と、右手の推定）で計算した（`placement_preview_report.json`）。
  - 4:3では、ライフルと同じく銃床が右端から外へ出る。
- ゲームで確認が必要なこと：
  - 銃口の位置（銃口炎）と、持つ位置（反動・リロードの回転の中心）。どちらも画像から読み取って配置ファイルに書く。
  - 射撃・反動・ADSへの移行・持ち替え・ダッシュの揺れのときの、画像の端の見え方。
  - ADS画像との整合（同じ銃に見えるか）。
  - 実機での見え方。

### 武器スキンの見え方

現行の方式は、描かれた明るさを残して、色相・彩度だけを置き換える。SMGの暗い本体に、ライフルと同じ試作色（緑）を当てる試しをした（`skin_trial_weapon_body.jpg`）。

- 試しの範囲は灰色の画素から近似したもので、正式のマスクではない。
- 結果：色は付くが暗い緑になり、ライフルの外装ほどはっきりは変わらない。
- 外装のどこを色替えの対象にするか、明るさの基準をどうするか（暗い本体のままでよいか）は、デザインとして決める必要がある。

### 先に決める項目（武器デザイン・方針）

1. **候補v2の形と配色を、SMGのデザインの基準にするか**：黒い本体、折りたたみのワイヤー銃床、グリップの前の弾倉、照星・照門。
2. **武器スキンで色を変える外装の範囲と、本体の明るさ**：暗い本体のままにするか、ライフルの砂色の外装のように色替えしやすい部分を設けるか。
3. 照準器：アイアンサイトのADSでよいか（D-042の方針どおり）。
4. 輪郭の太さの差（9〜11px と 6〜9px）を許容するか。
5. 性能（連射間隔・ダメージ・弾数・拡散など）。表示の確認には仮の値で足りるが、正式な値は別に決める（Q-011）。
6. ゲームでSMGを持たせる方法：確認用の一時的な切り替えにするか、武器の選択を作るか。

## 4. 候補画像の評価と推奨

**評価：画像としては、腰だめの素材に使える見込み。描き直しが必要な欠陥は見つからなかった。**

使える見込みの理由：
- ライフル腰だめと同じキャンバスで描かれている。
- 銃・手に欠けがなく、袖だけが下端から画面外へ続く。
- グローブ・袖・帯の配色と手の大きさが、採用ライフルとそろっている。

採用の前に必要なこと（修正ではなく、決定・作業）：
- 2値化した表示用画像を作る。
- デザインの判断（3章の1・2・4）。
- ADSとの整合と、ゲーム内の配置・動きの確認。

修正が要る可能性がある点：
- 輪郭がライフル腰だめよりやや太い。
- 本体が暗く、武器スキンの色が出にくい。

どちらもデザインの判断次第で、許容するなら修正は不要。

**次に行う作業（1つ）**：候補v2の形と配色を、SMGのデザインの基準にするかを決めること。外装の色替えの範囲を含む（3章の1・2）。

理由：ADSと全体図の制作依頼、外装の色替え領域、配置ファイルは、どれもこのデザインを前提にする。先に決めないと、後で作り直しになる。

### 最小限の素材でSMGを確認する作業順（案）

1. デザインの基準を決める（上の推奨）。
2. 腰だめの候補を採用するなら：表示用の派生、配置ファイル（銃口・持つ位置）、仮の性能、ADSの代わりの扱いを決める。今の仕組みはADS画像が必須なので、ADSができるまではゲームに登録しない。
3. ADSを制作する（ライフルのADSと同じ構図の決まり。照準器の先端が画面中央）。
4. 確認用に、ゲームでSMGを持たせる方法を用意する（コードの変更。方法は別に決める）。
5. Editorの3画面比で、腰だめ・ADS・移行・射撃・リロード・持ち替えを確認し、その後に実機で確認する。
6. 部位分割・領域マップを作り、手・腕と武器のスキンを確認する。
7. 装備画面用の全体図を作り、装備画面と一人称の対応を確認する。
