# 部品分離・色替え領域の設計（装備画面用素材）（2026-10-21）

ライフル横向き全体図と、標準プレイヤー正面立ち絵の設計資料。図：`layer_design.png`（レイヤー順）、`rifle_side_guide.png`・`player_front_guide.png`（範囲・領域）。数値：`layer_design.json`（作成：`Tools/pixelart/make_equipment_guides.py`）。

ここに書いた寸法・部品・配色は**制作のための提案**で、承認済みの仕様ではない。

## 1. 共通の規則

| 項目 | 内容 |
| --- | --- |
| キャンバス | 画像の種類ごとに固定。ライフル横向き **1760×800**、プレイヤー正面 **1024×1536**。同じ種類のレイヤーはすべて同じ寸法 |
| 基準点 | ライフル：銃口の先端 (360, 330)。銃身の中心線は y=330。プレイヤー：足元の中央 (512, 1456) |
| 余白 | ライフル：銃口の左に約260px（サプレッサー用）、レールの上に約170px（照準器用）、弾倉の下に約100px（拡張マガジン用）、右端に120px。プレイヤー：上140px、下80px、左右は手の外側から約200px |
| ドットの粗さ | 1ドット≈4px、黒い輪郭線6〜8px（採用済みの腰だめと同じ） |
| 背景・アルファ | 透明。描画部分はアルファ255（半透明なし） |
| トリミング | 個別のレイヤーを自動トリミングしない（位置がずれるため） |
| 原画 | 届いた画像はそのまま保持し、どのツールも書き換えない。アルファの2値化などは派生画像で行う（`Tools/pixelart/make_opaque.py`、しきい値128） |
| 画面上の大きさ | 装備画面のレイアウトに合わせて、表示側で整数倍・等倍・点補間で表示する（画像を縮小し直さない）。装備画面のレイアウトは未設計 |

### 色替え領域

| 領域 | 対象 | 今の実装 |
| --- | --- | --- |
| `weapon_body`（1） | タンの外装：ハンドガード・レールの山・機関部の下側の側板・弾倉受けの側板・銃床 | 一人称の腰だめ・ADSと同じ領域。今のスキン（`proto_rifle` / `test_green`）がそのまま効く |
| 固定 | 暗い鋼色（機関部の上側・銃身・照準器・銃口部品）、黒（弾倉・グリップ・床尾板）、赤い表示、線の黒 | 色替えしない |
| 後続の候補 | 弾倉・グリップの黒、照準器などの付属部品 | 領域を増やす実装が必要 |

一人称との対応：同じ `weaponId`（`proto_rifle`）と同じ `skinId` を使い、全体図の領域マップでもタンの外装を `weapon_body` にする。腰だめ・ADSで作った武器本体マスクと同じ規則（タン色の外装だけ、鉄部・照準器・赤い表示・線の黒は含めない）。

| 今の機能で反映できる | 追加実装が必要 |

| 色替えの計算（`SkinCatalog.FillColours`）・選択と保存（`SkinSelection`）・IDの対応 | UI上での色替え：今のシェーダーは `SpriteRenderer` 用。uGUIの `Image` で使うには、UI用のシェーダー（マスク・クリッピング対応）か、装備画面専用のカメラで `SpriteRenderer` を描く方式が必要 |

## 6. 届いた画像の検査と取り込み手順

1. **原画を保存して保持**する：`rifle_side_design.png`／`player_front_design.png`。以後どのツールも書き換えない。
2. **寸法を確認**する。指定（1760×800／1024×1536）と違う場合は、次のとおり扱う。
   - 補間による拡大・縮小はしない。ドットが崩れるため。
   - 実際の画像から基準点を読み取る。ライフルは銃口の先端・銃身の中心線・床尾の後端、人物は足元の中央・頭の上端。
   - 描かれた大きさが指定とほぼ同じなら、透明の余白の追加・削除だけで指定キャンバスに合わせる。基準点は整数のずれで合わせ、絵には手を加えない。
   - 描かれた大きさが大きく違う場合（目安±5%超）や、余白に描画がはみ出す場合は、そのまま使わない。ユーザーに報告し、再依頼するか、その寸法を正として基準点を記録するかを決めてもらう。
3. **向き・内容を確認**する。
   - ライフル：銃口が左であること。左右反転していても自動では反転しない。切り替え表示の側が変わってしまうため、報告する。
   - 描かれていてはいけないもの（手・背景・文字・影・取付部品）がないこと。
4. **ドットとアルファを確認**する。
   - 輪郭線の太さ（目安6〜8px）とドットの大きさを測る。
   - 半透明の画素数と、描画部分のアルファの値を記録する。
   - アルファを2値化した派生（`*_opaque.png`、`make_opaque.py`、しきい値128）を作る。
5. **一人称と照合**する。外装のタン・グローブ・袖の色が、一人称画像の色（`layer_design.json` の `paletteFromApprovedHip`）と同系か。部品の配置が腰だめ・ADSの銃と矛盾しないか。
6. **ユーザーの確認**を受ける。デザイン（提案部分を含む）の採否は、ユーザーが決める。
7. **承認後**に段階2の分離レイヤーを依頼し、届いたものを検査する。
   - 全レイヤーが同じキャンバス寸法であること。
   - 重ねたときに基準点と輪郭がずれないこと。
   - 隠れていた部分が描き足されていること。
   - 全レイヤーを重ねたものが承認済みの段階1の画像と矛盾しないこと。描き直された画像なので、画素の完全一致は求めない。
8. **マスクと領域マップ**を作る。
   - 部位分離の定義を書き、`split_layers.py`・`make_skin_regions.py` で作る。
   - 色漏れ・線の黒への混入がないことを検査する。
   - `skin_preview.py` で標準色と色違いを確認する。

段階1の画像を切り分けるだけでは、部品の裏側や装備の下は存在しない。分離に必要な下地は、段階2で描き足してもらう。
