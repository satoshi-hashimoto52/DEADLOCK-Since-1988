# 装備画面：iPhone 16 Pro 実機確認（2026-10-21）

装備画面（メニュー → 設定 →「装備・スキン（テスト用）」）と、一人称表示とのスキン連動を、実機で確認した記録。

画像2枚（ライフル全体図・プレイヤー立ち絵）は**制作候補のまま**で、正式採用ではない。色違い（`test_green`・`test_navy`）は検証用の仮配色。

## 1. 撮影用の構成と通常実行時の構成

| 項目 | 結果 |
| --- | --- |
| 前回のEditorの画像での「UIをワールド用カメラで描画」「一人称の武器を非表示」 | **撮影専用**。削除済みの一時テスト（`TmpCapture`、コミットなし）の中だけで行った変更 |
| 通常の実行時 | UIはオーバーレイ表示のまま（シーンの `m_RenderMode: 0`）。撮影用の設定や一時オブジェクトには依存していない |
| 実機での見え方 | ウィンドウ内はEditorの画像と同じ構成。ウィンドウの外側に、一人称の武器が暗いパネル越しに見える（武器は消していない） |
| 閉じたとき | メニューを閉じると入力のブロックが解除され、武器と操作が戻る。PlayMode `EquipmentScreen_OpenCloseEvents_InputBlockedOnlyWhileOpen_WeaponBack` と実機で確認。カメラは装備画面で変更していない |
| 繰り返し・シーン遷移 | 開閉とシーン遷移を繰り返しても状態は残らない（PlayModeと実機のログ） |
| 対戦中 | 装備画面はメニューの中の1画面。メニューの入力ブロックとオンラインで止めない動作は既存のまま（変更なし） |
| UI用シェーダー | `Deadlock/Skinned UI` はスキンカタログ → シーンのメニューから参照され、iOSビルドに含まれる。Metal向けに頂点・フラグメントとも4バリアントをコンパイル（`Logs/ios-export.log`）。ビルドの容量の記録にも含まれる（シェーダー9.2 KB、マテリアル0.3 KB）。実機での表示異常なし |

手順①〜⑤は、すべてユーザーの報告で「問題なし」だった。

| 手順 | 内容 |
| --- | --- |
| ① 標準表示 | 頭から靴まで、ライフル全体が見える。ノッチや画面端で隠れない。ぼけ・伸び・不自然な縁がない。ボタンを押しやすい |
| ② ライフルのみ | 全体図の対象部分だけが変わり、プレイヤーは変わらない。閉じると腰だめ・ADSにも反映される |
| ③ 手・腕のみ | 立ち絵の対象部分だけが変わり、胴・ズボン・頭部装備・靴などは変わらない。腰だめ・ADS・ナイフにも反映される |
| ④ 開閉・操作・保存 | 閉じると武器と操作が戻る。持ち替え・射撃・リロード・姿勢変更で崩れない。再表示・シーン変更・再起動の後も選択が残る |
| ⑤ 標準へ戻す | 立ち絵・全体図・一人称が元の色に戻る。再起動後も標準のまま。操作配置・透過率・ADS設定は導入前と同じ |

最後のスキンの選択：ユーザーの希望で、導入前と同じ「すべて標準」のまま。

## 5. 負荷

| 区分 | 計測方法・条件 | 結果 |
| --- | --- | --- |
| 起動直後の読み込み | `FrameRateMonitor` の10秒ごとの記録の最初の区間 | 最も重いフレームは約2.1秒（3回とも）。起動時の読み込みで、装備画面とは関係ない |
| 装備画面の初回表示 | 開いた直後1秒間の最も重いフレーム | インストール直後の1回目の起動：**131.8 ms**（1回）。再起動後（2回目・3回目の起動）の初回表示は17.7・18.0 ms |
| 2回目以降の表示 | 同上 | 9回、最大21.4 ms |
| 閉じる | 同上 | 10回、最大18.4 ms |
| 色替え | 同上（選んだ直後1秒） | 28回、最大19.6 ms |
| スクリーンショットの保存と重なった計測 | 同上 | 12回、117〜136 ms。保存処理の負荷で、画面の表示によるものではない（上の各区分から除いた） |
| 通常プレイ | 10秒ごとの記録 | 平均60 fps、最も重いフレームの中央値は約17 ms。約700・768 msの区間はアプリが一時的に裏へ回ったとき（`sceneWillResignActive` の直後） |

初回表示の131.8 msは、インストール直後の1回目の起動だけで起きた（再起動後は出ていない）。原因は特定していない。大きい画像2枚の初回の転送か、シェーダーの初回準備が考えられるが推測で、確認していない。
