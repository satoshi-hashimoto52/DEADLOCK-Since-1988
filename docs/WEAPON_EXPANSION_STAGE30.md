## 4. 通常武器3種類の設計案

### 4-1. ショットガン（`proto_shotgun`）

- 位置づけ：近距離専用。1回の発射で8発の散弾。距離で急に弱くなる。連射は遅く、反動は強い。
- 散弾：1回の発射で8発（1発の弾薬で8発）。散弾ごとに減衰と命中を計算する。
- 拡散：散弾の広がりは円錐（腰だめ6°、ADS 4.5°）。ADSでもまとまりすぎないようにする。
- 同じ対象への複数命中：ダメージは足し合わせる（散弾8発がすべて当たって最大）。命中の表示（ヒットマーカー）は1回の発射で1回にまとめる案。
- リロード：**最初は、今の「一度に満たす」方式で作る**（コードを増やさない）。1発ずつ込める方式（途中で撃てる）は、ショットガンらしいが新しい処理が必要なので、ユーザーの判断（未決定）。
- ADS：使える。拡散の縮小は小さく、FOVの変化も小さい。
- 弾道の線：8本すべては出さない。今の上限6本のままだと古い線が消えるので、**散弾は代表の3本だけ描く**案（描画だけの省略で、命中は8発とも計算）。
- 演出：銃口炎は大きめ（専用の画像の案、素材の文書）。反動は強い・縦。
- PvP／PvE：最大ダメージは96（1発で倒せない）。2回の命中でHP100を倒す。ゾンビ（HP100、近づいてくる）には強いが、10m以上の撃ち合いでは不利にする。

### 4-2. ハンドガン（`proto_handgun`）

- 位置づけ：取り回しがよく、単発の精度が高い。装弾数は少なく、リロードは短い。
- 装備枠：案Aではメイン枠（3章）。
- 発射：単発（押すたびに1発、`automatic=false`）。最短の間隔0.15秒（連打の上限400RPM）。間隔より早い入力は今の仕組みどおり捨てる（予約しない）。
- ADS：使える。ADS時間が短い（0.14秒）。
- 持ち替え：短くしたい（0.25秒）が、今は全武器共通の値なので、武器ごとの持ち替え時間の欄が必要（7章、未実装）。
- 移動中の精度：移動の影響を小さくしたい。移動中の拡散は未実装なので、欄を追加する場合の案として値を置く。
- HUD：側面図は小さい銃なので、弾数パネルの中で小さく見える（素材の文書で、キャンバスの中の大きさを決める）。

### 4-3. 軽機関銃（`proto_lmg`）

- 位置づけ：大容量の弾倉で撃ち続けられる。反動は強めで、ADSと移動は重い。弾の消費が多い。
- 装弾数75、リロード4.0秒（長い）。発射速度はライフルより少し速い700RPM。
- 連射中の反動：`RecoilProfile` の複合（上＋左右交互）・強。連射で広がる仕組みは未実装なので、反動で扱う。
- 腰だめの精度は低く（2.4°）、ADSは0.35°。ADS時間0.32秒、ADS中の移動の倍率0.45。
- 表示：一人称の画像は大きく、HUDの側面図は横長。
- 弾数HUD：今の「装弾数 / 予備弾」の表示のまま3桁に収まるか確かめる（「75 / 150」）。

※ 1発ずつ込める方式を採用する場合は「1発0.5秒、最初に0.3秒」の案（未決定）。

### 5-1. 根拠（HP100、頭の倍率なし、全弾命中のとき）

| 武器 | 倒すのに必要な命中 | 最短の時間（近距離） | 考え方 |
|---|---:|---:|---|
| ライフル（現行） | 4発 | 0.30秒 | 基準 |
| ショットガン | 2回の発射（8発中7発以上の命中が2回） | 0.90秒 | 1発で倒せない。近距離ではゾンビ・人とも確実に効き、10mを超えると急に弱い。総合では「近距離で外さない武器」 |
| ハンドガン | 4発 | 0.45秒（連打の上限） | ライフルより遅い。移動・ADS・持ち替えの軽さで補う |
| LMG | 5発 | 0.34秒 | ライフルより少し遅い。75発で撃ち続けられる代わりに、リロード4秒・ADSが重い・移動が遅い |
| 試作型特殊SMG | 6発 | 0.32秒 | SMGの案A（17・900RPM、6発・0.33秒）よりわずかに速い。代わりに装弾数・リロード・遠距離が不利（EPICの文書） |

- PvPとPvEの極端な差を避けるため、1発で倒せる武器は作らない（ショットガンの最大96）。
- 弾薬箱の30発（全武器共通）は、ショットガン（予備48）と LMG（予備225）で効き方が大きく違う。武器ごとの取得量か弾薬の種類が必要（未決定）。
- SMGの値（案A）が未承認なので、EPIC SMG の数値は暫定の比較。

### 5-2. ユーザーの判断が必要な値

- SMGの正式な値（EPIC の基準になる）。ライフルの値を変えるかどうか（今回は変えない）。
- ショットガンのリロード方式（一度に／1発ずつ）。散弾数（8）と1発のダメージ。
- 移動中の精度・持ち替え時間・移動速度の欄を追加するかどうか（新しい仕組み）。
- 弾薬の種類（拳銃弾・ライフル弾・散弾など、GAME_SPEC §8 で「提案」）と弾薬箱の量。
- 反動の強度の倍率（弱0.7・中1.0・強1.4、Phase 1 の試験用の値）を製品で使うか。

## 6. 武器定義データの変更案

既存の欄は変えない。新しい欄はすべて「初期値なら今の動き」にし、ライフル・SMGの動きとアセットが変わらないようにする。

| 欄（案） | 型 | 初期値 | 使う武器 |
|---|---|---|---|
| `category` | 列挙（Rifle・SMG・Shotgun・Handgun・LMG） | Rifle | 全武器。調整ラボの `TypeOf` をこれに置き換える |
| `pelletsPerShot` | 整数（1以上） | 1 | ショットガン |
| `pelletTracers` | 整数 | 1 | ショットガン（描く線の数） |
| `reloadMode` | 列挙（Magazine・PerRound） | Magazine | ショットガンを1発ずつにする場合だけ |
| `switchTime` | 秒（0なら共通の値） | 0 | 武器ごとの持ち替え |
| `moveSpreadMultiplier` | 倍率 | 1（影響なし） | ハンドガン・LMG・EPIC |
| `moveSpeedMultiplier` | 倍率 | 1 | LMG・ハンドガン |
| `ammoPickupAmount` | 整数（0なら箱の値） | 0 | ショットガン・LMG（弾薬の種類が決まるまでの仮） |

- レアリティは武器の性能ではないので、`WeaponDefinition` には入れない（ガチャの目録に持つ。EPIC の文書）。
- 調整ラボ：新しい欄を調整項目と表の列に足し、保存形式の版（`profileVersion`）を2にする（版1の保存データは読まない）。

## 8. 実装順序の提案

基本案（第31〜34段階）を検討した結果、次の点から分け方を変える案を出す。

- オンラインでは今も全員がライフルで、武器IDを通信していない。散弾には発射要求の変更も必要で、影響が大きい。
- ガチャは、ポイント・所持品・保存・装備画面のどれもないので、「ガチャ接続」の前に土台が必要。
- EPIC SMG の性能は、SMG の正式な値に対して決める必要がある。

| 段階 | 内容 | 完了の条件 |
|---|---|---|
| 第31段階 | 通常武器3種類のデータと射撃（**オフライン**）：新しい欄（初期値で従来どおり）、散弾、3つのアセット、開発用の銃の選択、調整ラボの対応。画像は仮（側面図なしでも名前が出る） | ライフル・SMGのテストが変わらず合格。新しい武器のテスト |
| 第32段階 | 通常武器の画像（AssetPipeline で承認・登録）とUnityの表示：側面図・腰だめ・ADS・銃口炎、HUD・装備画面、iPhone・iPad | 画像の承認、表示の確認 |
| 第33段階 | SMG の正式な値の決定（ユーザー）と、試作型特殊SMG の性能・専用外観（オフライン） | SMG と EPIC の比較の確認 |
| 第34段階 | 所持品・保存・ロードアウトの土台（ガチャなし）：所持している武器だけを選べる、保存の版 | 保存の互換性、所持の判定 |
| 第35段階 | ガチャの接続（開発用のポイント・確定の排出でテスト）。排出確率・確定枠は、ユーザーが決めた値だけを使う | 排出・所持・重複・保存のテスト |
| 別の段階 | オンラインの武器の同期（武器ID、散弾の発射要求）、案B（銃の枠2つ）を採用する場合はその変更 | オンラインのテスト |
