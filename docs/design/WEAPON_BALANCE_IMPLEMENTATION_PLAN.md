## A. 既存処理と追加する調整項目の接続

| 既存の要素（PROGRESSに記載） | 確認できる役割 | 追加／検証したい項目 | 導入時の注意 |
|---|---|---|---|
| 武器定義（`Weapon_ProtoRifle`、SMGは試作定義） | 威力・発射間隔・装弾・弾速等の試作値 | 武器ID単位のパラメータ定義、距離減衰参照 | ライフル現行値を上書きせず別の試験プロファイルを作る |
| `WeaponViewProfile` | ADS/手元画像、見た目のキックと反動 | カメラ反動／スプライト反動の分離、反動軸・強度 | 手元絵の揺れと命中方向を混同しない |
| 毎フレーム移動＋区間Raycast弾道 | 弾速・最大到達距離・命中 | 命中距離から補正倍率を求める | 飛翔中の貫通／跳弾・部位別倍率はまだ未決定 |
| `AuthoritativeWeaponState` | ホストが弾数・発射間隔・命中ダメージを判定 | 武器別定義の選択・ホストによる補正適用 | オンラインでクライアント申告のダメージ値を信用しない |
| `DevGunSelection` | 射撃場／トレーニングでライフルとSMGを一時切替 | 試験用プロファイルを選び直す導線 | 現行の選択は保存しない、製品版の装備UIと切り分ける |
| 射撃場 `Proto_FiringRange` | 静的ターゲット・射撃表示 | 10/25/40/60/80mの比較・命中率ログ | 既存ステージは16×60m。80m以上は別検証手段が必要 |
| `PlayerInputRouter`、ADS | タッチ／PC入力を管理 | 試験UI操作中の射撃誤入力対策 | UIから閉じるとき押下状態を持ち越さない |

## B. 開発者用パラメータ編集UI案

通常ユーザーには表示しない**開発ビルド／Unity Editor専用**の一画面を提案。実装方法（EditorWindowか開発ビルド内画面か）は未決定。

1. **上段**：武器一覧（武器種×性能表）、現行値・調整中値・差分、データセットIDを表示。
2. **反動**：軸［縦／横／斜め／複合］、上下［上／下／なし］、左右［左／右／交互／なし］、強度［弱／中／強］、反動角度、ADS係数、回復時間。
3. **距離補正**：距離mと倍率の制御点一覧、グラフ、距離指定時の実ダメージ表示。点を追加・削除しても昇順制約を保つ。
4. **射撃場操作**：適用（試験セッション限定）／初期値に戻す／比較候補をエクスポート。採用／製品版反映はUIから自動実行しない。
5. **結果**：距離別のダメージ、平均反動角、拡散と着弾分布、命中率、連射時間、リロード込みDPS（算出方式を明記）。

### 保存方針

- 現行の本番用ScriptableObjectの破壊的上書きを禁止。
- 調整中データは試験用の独立ファイルとする（例：`Assets/Game/BalanceLab/Profiles/`。**新規予定パスであり現存は未確認**）。
- `weaponId`、`profileVersion`、`baseCommit`、各パラメータ、距離制御点を持つ形式を検討。
- 調整と実装への採用は別工程。未採用の試験値はユーザーの端末の製品設定に混入させない。

## C. 反動の動作定義案

- `kickYawDegrees` と `kickPitchDegrees` を武器ごとに計算。上方向はピッチを上げる、左右方向はヨーを動かす。Unityの実座標符号は実装時に確認する。
- 弱／中／強は基準角度にかける3つの係数。係数は**未確定**（前資料の0.7/1.0/1.4は例）。
- 斜め反動は縦横成分を比率で配分。方向指定は左右・上下の組合せで表現する。
- 左右交互は、単純な奇偶発射番号で切り替える案。バースト・リロード後に番号をリセットするか未決定。
- 乱数を採用する場合は再現可能なseedを使用し、少なくとも射撃シミュレーション結果が端末間で変動しない設計を検討する。
- **反動**（狙点移動）と**拡散**（狙点付近の発射方向のばらつき）を別パラメータにする。武器画像のキックも別。
- モバイルの視点操作・ADS・姿勢・連射と干渉するか試験する。

## D. 距離補正の動作定義案

- 制御点 `(distanceMeters, multiplier)` を距離昇順に保持し、区間内は線形補間。
- 近い端点未満は最初の倍率、遠い端点超過は最後の倍率を使う。**最大到達距離を超えた弾は別途無効**。
- 非負距離、有限倍率、重複距離なしなど入力検証を行う。
- ダメージ計算の整数化／ヒット部位倍率／障害物判定の順序は未確定。ホスト側で一度だけ適用する。
- UIプレビューは最終ダメージを整数で表示する場合、丸め方式を選んでから結果を示す。

## E. 必須回帰テスト（実装する場合）

| 分野 | 条件 | 期待結果 |
|---|---|---|
| 反動 | 縦・横・斜め・左右交互と3強度 | 指定方向・相対的な強さが再現する |
| 反動 | ADSと腰だめ、発射停止からの回復 | それぞれの係数・回復が独立して働く |
| 距離 | 制御点上・中間・上下端・最大射程外 | 倍率・補間と命中可否が整合する |
| 射撃 | フルオート連射、弾切れ、リロード、武器切替 | 既存の弾数・射撃間隔・操作ルールを維持 |
| PvE | ゾンビ命中、壁で遮断、再挑戦 | 二重ダメージや旧プロファイル残留がない |
| PvP | ホスト・クライアントの異なるローカル試験値 | 権威側の武器定義に基づき結果が確定する |
| モバイル | タッチ＋ADS＋試験UI | 操作が貫通しない、押下状態が残らない |
| データ | プロファイルの復元と比較 | 未採用設定が製品版に流入しない |

## F. 別ブランチから実装ブランチへの取り込み案

`feature/weapon-balance-lab` は**実験・比較の作業ブランチ**。統合側 `feature/integration-smg-dungeon` はユーザーが採用した設定のみ受け入れる。

- 実験中はレビュー用PRをドラフトで開くことは可能。ただしユーザーの承認なくPR作成・マージはしない。
- 試験用UIや診断ログまで本番に入れるかは別判断。完成時には**採用するデータおよび必要な計算コードのみ**を選ぶ。
- 取り込み後のコードとデータが同じバージョンであることをテストする。
- ローカルClaudeが統合ブランチで作業中なので、当面はGitHub上の専用ブランチにDocsだけを追加する。
