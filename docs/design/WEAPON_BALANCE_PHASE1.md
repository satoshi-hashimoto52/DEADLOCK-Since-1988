## 1. 既存実装の調査結果（コードで確認）

| 項目 | 実装 |
| --- | --- |
| 武器定義 → 発射 | `GunController.Update` が入力から `TryFire` を呼ぶ。`definition.fireInterval` で間隔、`AmmoState` で弾数、`ApplySpread` で拡散した方向を作り、`ProjectileSystem.Fire(origin, dir, projectileSpeed, maxRange, damage, shooter)`。オンラインでは `ShotOverride` がホストへ要求を送る |
| 反動 | `FirstPersonMotor.AddRecoil(pitch, yaw)`（pitch は上が正、yaw は右が正。回復は motor の `recoilRecovery`）。従来は縦が固定値、横が毎発ランダム（±recoilYaw）、ADS は `adsRecoilMultiplier` |
| 弾道・命中 | `ProjectileSystem.Step` が毎フレーム速度×時間だけ進め、区間を Raycast。射程は `RemainingRange`。命中時に `IDamageable.ApplyDamage(Damage)` |
| ダメージ確定 | オフライン：撃った端末の `ProjectileSystem`。オンライン：ホストの `NetworkAvatar.ServerFire` が `AuthoritativeWeaponState.TryFire`（弾数・間隔・リロード・死亡）で検査し、ホストの `ServerProjectiles` に**ホスト自身の武器定義**の威力で撃つ。クライアントは発射位置と方向だけを送り、威力や命中は送らない |
| 武器切り替え | 射撃場などのオフラインのシーン：`DevGunSelection`（メニューの「銃（テスト用）」、ライフル⇄SMG候補、アプリの起動中だけ）→ `GunController.SetDefinition`（弾薬は満タンから）。オンラインのアバターは `Net_Avatar.prefab` に設定されたライフルのアセットを使う |
| 武器データの参照 | `WeaponDefinition`（ScriptableObject）：`Weapon_ProtoRifle.asset`（proto_rifle）、`Weapon_ProtoSMG_Candidate.asset`（proto_smg、性能はライフルと同じ値） |

## 2. 追加したもの

### 2.1 製品のコード（Deadlock.Runtime）— 設定がなければ従来どおり

- `RecoilProfile`（反動の設定）と `RecoilCalculator`（反動の計算）：
  - 軸：縦方向／横方向／斜め／複合。上下：なし・上・下。左右：なし・左・右・左右交互。
  - 組み合わせの検証：縦方向＝上か下で左右なし、横方向＝左右（交互を含む）で上下なし、斜め＝上か下＋左か右、複合＝上か下＋左右交互。数値は有限で、角度は0以上、ADS倍率は0〜1。
  - 強度：弱0.7・中1.0・強1.4（**試験用の倍率。製品のバランスとしては未確定**）。
  - 基準角度は縦（pitchDegrees）と横（yawDegrees）を別に持つ。ADS は `Lerp(1, adsMultiplier, ADSの進み具合)` を掛ける。
  - 左右交互は発射番号で決める（偶数＝右、奇数＝左）。乱数は使わない。
  - 発射番号は、射撃が 0.5 秒（または発射間隔の2倍）より長く途切れたとき、リロード、武器の交換、リスポーンで 0 に戻る。
  - 拡散（`ApplySpread`）は反動と別のまま。
- `DamageFalloffProfile`（距離減衰）：制御点 (距離 m, 倍率)。点の間は線形補間、最初の点より手前は最初の倍率、最後の点より遠くは最後の倍率。検証：距離は0以上・昇順・重複なし、倍率は0〜1、NaN と Infinity は不可。不正または空なら倍率1.0。
- `WeaponDefinition` に任意の欄 `recoilProfile`（初期値は無効）と `damageFalloff`（初期値は空）を追加した。既存のアセットはどちらも無効と空のままで、威力・反動は変わらない。
- `GunController`：反動の設定が有効かつ正しければ計算器の値を使い、そうでなければ従来の反動。`LastRecoil`（最後の反動）と `ShotIndex`（発射番号）を公開。
- `ProjectileSystem.Fire` に、距離減衰を渡せるオーバーロードを追加した（従来の呼び方は倍率1.0）。命中時の距離は、発射点から命中点までの直線距離（貫通・跳弾を入れる場合は、累積の飛翔距離に変えるかを別に検討する）。実ダメージ＝基本威力×倍率。最大射程と弾速は従来どおり。命中の情報に、距離・倍率・実ダメージを追加した。
- オンライン：ホストの `NetworkAvatar.ServerFire` は、**ホストの武器定義の** `damageFalloff` を渡すだけにした（今のアセットは空なので、ダメージは従来どおり）。クライアントの値は使わない。開発用の試験値は、オンラインのアバターの武器定義（`Net_Avatar.prefab` のライフルのアセット）には届かない。

### 2.2 開発用（Deadlock.Dev。Editor と開発ビルドだけでコンパイル、リリースビルドには入らない）

- `WeaponBalanceProfile`：1つの武器の試験値（武器ID、種類、profileVersion、baseCommit、保存日時、性能の各項目、反動、距離減衰）。`FromDefinition`（現行値）、`ApplyTo`（実行時の**コピー**に書く）、`Problems`（適用できない理由）、表の列の定義、差分。
- `WeaponBalanceStore`：試験値を JSON で保存する（`Application.persistentDataPath/WeaponBalanceLab/<weaponId>.json`）。PlayerPrefs やゲームの設定とは別。読み込むのは、同じ武器IDで同じ版の形式のものだけ。
  - baseCommit：Editor では `git rev-parse HEAD`、実機では取得できないので「unknown (build <バージョン>)」と記録する。
- `WeaponBalanceLab`（調整画面）：射撃場のメニューの右上「開発 武器調整」（タイトルロゴと重ならない幅140の2行のボタン）から開く。Editor ではメニュー DEADLOCK/Dev/Weapon Balance Lab をオンにしたときだけ。
  - 上段：武器を行、パラメータ18列の一覧（横スクロール）。編集した列は「現行→編集値」を色付きで表示。行を押すと、その武器を選ぶ。
  - 中段のタブ：性能（12項目を−／＋で変更）、反動（軸・上下・左右・強度の切り替え、縦と横の基準角、ADS倍率、縦の基準角のスライダー、従来の反動に戻す、組み合わせの検証、1〜4発目の角度、8発の累積パターンの図）、距離減衰（制御点の一覧・追加・削除・距離±5m・倍率±0.05・倍率のスライダー・試験例・初期値に戻す、折れ線グラフ、10/25/40/60/80m の倍率と実ダメージの現行→編集）、試射・保存（試射に適用、試射を終了、保存、読み込み、編集を現行値に戻す、保存データを削除、最後の命中の距離・倍率・ダメージ、現行値との差、適用できない理由）。
  - 試射に適用：選んだ武器の定義を実行時にコピーし、編集値を書いて装備する。武器のアセットは書き換えない。試射の終了、メニューでの銃の切り替え、シーンを出ることで、正式な値に戻る。
  - 開いている間はプレイヤーの入力を止める（`PlayerInputRouter.Block`）。画面全体が操作を受け止めるので、射撃・視点操作に通らない。閉じたときに押下状態は残らない。

## 2.3 追加（2026-10-27、未コミット・ユーザーの実機確認待ち）

- 反動の回復（調査結果）：`FirstPersonMotor` は、発射の反動を同じフレームで照準に加え、その一部を一定の速さで戻す。これまでは戻る割合が0.5（コードに固定）、速さがシーンの `recoilRecovery`（9°/秒）だった。連射中は、戻りきる前に次の反動が積み重なる。射撃をやめても戻り続ける。ADS では反動に ADS 倍率が掛かるだけで、戻り方は同じ。
- 回復量と回復速度を分けた：`RecoilProfile.recoveryFraction`（回復量＝反動のうち戻る割合、0〜1、既定0.5）と `recoverySpeed`（回復速度、°/秒、0.5〜60、既定9）。どちらも範囲外・NaN は不正として扱う。反動の設定が無効なら、従来どおり（半分を、シーンの速さで戻す）。`FirstPersonMotor.AddRecoil(pitch, yaw, recoveryFraction)` と `RecoverySpeedOverride` で受け取る。
- 方向の選び方：上下（なし・上・下）と左右（なし・左・右）を別々に選び、軸は組み合わせから自動で決まる（`RecoilProfile.SetDirections`／`AxisFor`）。左右交互は独立した切り替え。上下と左右の両方を「なし」にはできない。
- 予想反動に、回復込みの視点の動き（緑、各発の直後と停止1秒後）を加えた。編集中の RPM で8発撃ったときの値を、モーターと同じ規則で計算する。
- ゲーム画面の調整パネル（`WeaponBalanceQuickPanel`、開発用）：射撃場の上部「反動調整」で表示・非表示。タイトルをドラッグして動かせる。パネルが受け取るのは自分の範囲のタッチだけ。マウスの場合は、パネルの上にある間だけプレイヤーの入力を止める。（2.4 で作り直した）
- 武器アセットの差分：iOS の書き出しなどで `AssetDatabase.SaveAssets` が呼ばれると、新しい欄が初期値のまま書き込まれていた。そこで、エディタのメニュー DEADLOCK/Dev/Write Weapon Definition Fields（`WeaponDefinitionAssets.WriteAllFields`）で全欄を明示的に書いた。追加されたのは、無効・空の初期値の欄だけ。既存の値と GUID は変えていない。その後のテストと iOS ビルドでは、差分は出ていない。

## 2.4 A/B比較への再設計（2026-10-27、未コミット・ユーザーの実機確認待ち）

- A／B：A＝試射で今使っている値（読み取り専用。試射していない武器は正式値）、B＝編集中の値（`WeaponBalanceLab.Applied(id)`／`Edited(id)`、武器ごとに別のデータ）。Bを編集してもAと試射は変わらない（2.3 の「試射中にすぐ反映」は廃止）。「Bを試射に適用」でだけ、Bのコピーを試射に入れ、Aをその値に更新する。「BをAに戻す」はBだけをAの値に戻す。試射の終了でAは正式値に戻る（Bは残す）。製品のアセットと正式な性能値は書き換えない。
- 武器の選択：ドロップダウン（`WeaponPicker`）。一覧は開くたびに、ラボに登録された武器（射撃場の銃の候補 `DevGunSelection.Options`）から作る。表示名は武器定義の `displayName` と種類。武器を足しても UI の改修はいらない。
- 反動の編集行（`WeaponRecoilEditor`）：簡易パネルと詳細画面で同じ部品を使う。各行の左がB（方向ボタン＋スライダー＋数値入力）、右がA。AとBが違う行は色が付き、差分はすぐ更新される。
  - 上下：`[上|下|なし] ──●── [0.70]`、左右：`[左|右|なし] ──●── [0.25]`。「なし」にするとスライダーと数値入力が無効になり、角度の値は残る（その間の角度の変更は理由を示して断る）。
  - 強度（弱・中・強）と左右交互（ON/OFF）、ADS反動倍率、回復量、回復速度。
  - スライダーの粗調整（全範囲。角度・倍率 0.05、回復速度 0.5°/秒）と微調整（値の前後の狭い範囲。角度 ±0.5°を0.01、倍率 ±0.1を0.01、回復速度 ±3を0.1）。
  - 数値の直接入力：範囲（角度0〜10°、倍率0〜1、回復速度0.5〜60°/秒）の外や数値でない入力は、理由を表示して断る（勝手に丸めない）。
- 照準リセット：視点を基準の向き（射撃場に入ったときの向き。「今の向きを照準の基準に」で変更可）に戻し、反動の未反映分・回復中の分を消し、次の発射を反動パターンの1発目にする（`GunController.ResetShotSequence`、開発用の呼び出しだけ）。パラメータ・弾数・ADS・装備は変えない。パラメータのリセット（「Bを正式値に」）とは別の操作。
- 簡易パネルの表示：通常は小さく（武器名、試射の状態と未適用の差分の数、Aの方向・強度・縦横の角度、回復量）。「展開」で、実測の反動・ADS・回復速度と残り、A/Bの編集行、操作ボタン（Bを試射に適用、BをAに戻す、試射終了、照準リセット、照準の基準、Bを正式値に）。最初の位置は、Safe Area の中で、照準（画面中央）と HUD の操作部品に重ならない場所を計算で選ぶ（ドラッグ後はその位置を保つ）。
- 詳細画面：タイトル行に武器のドロップダウン。反動タブは同じ編集行と操作ボタン、予想反動の図（灰＝A）。試射・保存タブに「BをAに戻す」「照準リセット」、AとBの差の一覧。4:3 の画面幅に収まるよう、状態・メッセージ欄とタブの幅を詰めた。

## 2.5 簡易パネルの拡大・射撃場の無限予備弾（2026-10-27、未コミット・ユーザーの実機確認待ち）

- 簡易パネルを指の操作向けに作り直した（`WeaponBalanceQuickPanel`、反動の編集行は `WeaponRecoilEditor` のタッチ用レイアウト）。iPhone 16 Pro の横画面（高さ402pt＝キャンバス941単位、1pt≈2.34単位）を基準に、ボタン・スライダー・数値入力の高さを44pt相当（104単位）以上にした。文字は約11〜15pt。
  - 上段（固定）：移動用のつまみ「≡」、武器のドロップダウン（項目も44pt）、展開／縮小、閉じる。
  - 小さい表示：試射の状態と未適用の変更の数、Aの主要な値と回復量。
  - 展開表示：中段は内部スクロール（実測値、A/Bの編集行、試射を終了、照準の基準、Bを正式値に、詳細画面）。方向の行は、ボタンと数値入力の行と、その下のスライダーの行の2段。下段（固定）：Bを試射に適用、BをAに戻す、照準リセット。
  - 展開時の高さと位置は、照準とHUDの操作部品（画像）に重ならない範囲で一番高くなるよう計算する（HUDの文字は、避けられないときだけ重ねる。入りきらない分はスクロール）。iPhone 16 Pro（実機の配置）では幅299pt・高さ190pt。開いている間は「反動調整」ボタンを隠す。
  - 詳細画面の反動タブは、従来の1行のレイアウトのまま（同じ部品・同じ操作）。
- パネルの背景：背景の画像の色だけを不透明度0.5にした（CanvasGroup は使わない）。文字・ボタン・スライダーのつまみは不透明。背景の上の文字には黒い縁取りを付けた。枠線は背景とは別の4本の不透明な線（背景の画像に縁取りの効果を付けると、背景そのものが重ねて描かれて透過が消えるため）。選択中のボタンは不透明な橙色。
- 射撃場の無限予備弾（Proto_FiringRange のみ）：
  - 弾薬箱：`PrototypeSceneBuilder` が射撃場に置いていた2つ（`BuildPickups`）を、射撃場では置かないようにし、シーンからも取り除いた。訓練場と遺跡の弾薬箱はそのまま。
  - `FiringRangeAmmo`（射撃場のプレイヤーに付ける部品）が `GunController.InfiniteReserve` をオンにする。`AmmoState.InfiniteReserve` がオンのときは、リロードで弾倉を満たしても予備弾を減らさない。装弾数・リロード時間・リロード中に撃てないこと・弾倉への補充の仕方は、武器の定義どおり。初期値はオフで、ほかのモードとオンラインの弾の管理（`AuthoritativeWeaponState`）には影響しない。部品はシーンに属するので、射撃場を出ると無くなる。
  - 表示：射撃場では弾数を「30 / ∞」と表示する（30は武器の装弾数）。

## 2.6 調整パネルの配置の最適化（2026-10-28、未コミット・ユーザーの実機確認待ち）

- ゲーム中の調整パネル（`WeaponBalanceQuickPanel`）：
  - 幅は620単位（以前の700から約11%狭い）か504単位。展開時に照準とHUDの操作部品を避けた位置で、504単位のほうが32単位以上高くなる場合（または504単位だけが重ならずに置ける場合）は504単位にする。移動スティックと照準の間の縦長の空間に入るため。HUDの文字（HP表示など）は避けるが、避けるために低くなるのは1行分（112単位）までとし、それ以上低くなる場合は文字に重ねて高さを優先する（空の文字は障害物として扱わない）。
  - 高さはSafe AreaとHUDの操作部品から毎回計算する（固定値ではない）。
  - 操作部品は1マス104単位（iPhone 16 Pro横画面で44pt）のマスに入れる。マス全体がタッチを受け、見た目は上下10・左右4単位内側に描く（ボタンの見た目の高さ84単位）。隣り合うマスは重ならない。
  - 上段：移動用のつまみ、武器のドロップダウン（長い名前は「…」で省略、開いた一覧は正式名）、展開／縮小、閉じる。2段目：状態（試射の有無、A/Bの差分の項目数、メッセージ。縮小時はAとBの主な値も）と、展開時はスライダーの粗／微の切り替え。
  - 展開時の本体（内部スクロール）：方向は2行（1行目：方向ボタンと数値、2行目：スライダーとAの値）、強度と左右交互は1行、ADS反動倍率・回復量・回復速度はそれぞれ1行（スライダー・数値・Aの値）。その下に補助操作（試射終了、照準の基準、Bを正式値に、詳細画面）と実測値。下段（固定）：Bを試射に適用、BをAに戻す、照準リセット。
  - スライダーは、横向きに動かし始めた指でだけ値が動き、縦に動かし始めた指は本体のスクロールになる（`TouchSlider`）。タップはその位置の値。数値欄も、入力中でなければ縦の指でスクロールする（`TouchInputField`）。
  - 文字は以前より約10〜15%小さい（ボタンと数値30単位、ラベルとAの値26単位、状態24単位）。
- 詳細画面の反動タブ：
  - 反動の行は、左端から予想反動グラフ（右端420単位）の手前まで伸び、スライダーが残りの幅を使う。B（数値と単位）とAの列は右側で全行同じ位置にそろう。
  - 上段の武器ドロップダウンは、タイトルと閉じるの間で、開発用のFPS表示を避けた一番広い場所に置く（画面を開くたびに計算）。名前は「…」で省略し、一覧は正式名で、一覧は窓の中に収まる。
- 数値の単位をそろえた：0.70°、0.25°、0.55倍、50%、9.0°/秒。回復量は%で表示・入力する（内部は0〜1の割合のまま。製品の値と保存形式は変えていない）。

## 2.7 反動設定の状態維持・パネルを詳細画面と同じ行に・武器選択と装備の連動（2026-10-28、未コミット・ユーザーの実機確認待ち）

- 調査結果（PlayModeで記録）：Bの編集は銃・照準・発射番号・回復中の反動を何も変えない。「Bを試射に適用」は、銃の定義の差し替えに `GunController.SetDefinition`（武器の持ち替え用）を使っていたため、発射番号が0に戻り（反動パターンが1発目から）、弾倉が満タンになり、ADSが解除され、引き金を一度離すまで撃てなかった。照準・蓄積した反動・回復中の反動は変わっていなかった。「Bの反動を正式値に戻す」（旧表示「B反動を正式値に」）と「Bを正式値に戻す」はBだけを変え、銃・A・照準は変えない。武器アセットへの書き込みはない。
- 修正：同じ武器の値だけを差し替える `GunController.SetDefinitionKeepingState` を追加し、「Bを試射に適用」と「試射を終了」で使う。発射番号・発射間隔・ADS・リロード中・押したままの引き金・弾数（新しい弾倉の大きさまで）を引き継ぎ、新しい値は次の発射から使う。照準と反動は `FirstPersonMotor` のもので、触らない。照準リセットだけが明示的に初期化する。発射を止めて0.5秒たつと発射番号が0に戻るのは従来どおり（パターンの区切り）。
- ゲーム中のパネル：反動の行を詳細画面と同じ部品・列（`WeaponRecoilEditor` の Inline。行の高さ50単位、文字19単位、方向ボタンとスライダーと数値とAが1行）にした。幅は680・600・540単位から、照準とHUDの操作部品を避けて一番高くなるもの（狭いほうは32単位以上高くなるときだけ）。上段・状態・下段も詳細画面に近い大きさ（上段52単位、下段50単位）。各操作部品は見た目の範囲でタッチを受け、隣とは隙間がある（44ptのマスはやめた。詳細画面と同じ）。
- 武器のドロップダウン（ゲーム中・詳細画面とも）で選んだ武器を、`DevGunSelection` を通して実際に持つ（メニューの「銃（テスト用）」と同じ選択）。Aは武器ごとに保持し（試射中の武器を持ち替えても、戻ればその武器の試射の値で撃つ）、Bも武器ごと。メニューから持ち替えた場合は試射を終了し、パネルは手に持っている武器を表示する。射撃場だけの開発機能。
- 詳細画面の微調整の 0.92（期待 0.87）は、スライダーの誤りではなかった。微調整の範囲は、値が範囲内にある間は開始位置を保つ（指の下でつまみが跳ばないため）。実機検証で、直前の操作で範囲が0.55〜1.55のまま1.00を入力したため、37段目は0.92が正しかった。検証側の期待値を直した。
