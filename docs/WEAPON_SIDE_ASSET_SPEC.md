# 武器側面画像の共通規格（weapon_side）

武器の横向き全体図（弾数HUD・装備画面などで使う画像）の、全武器共通の規格。
AssetPipeline の分類 `weapon_side`（`AssetPipeline/config/assets.json`）がこの規格で検査する。

## 1. 機械検査（AssetPipeline が判定。1つでも外れたら不合格）

| 項目 | 規格 |
| --- | --- |
| 形式 | PNG（署名・チャンクのCRC・画素データ全体が正常に読めること） |
| 解像度 | 1440×800 px ちょうど |
| 色形式 | RGBA（PNGのカラータイプ6）、8bit/チャンネル |
| 背景 | 透明。完全に透明な画素があること |
| 収まり | 画像の外周1画素がすべて完全透明（武器がキャンバスの端に接していない＝全体が内側に収まっている） |
| 内容 | 描かれた画素（アルファ > 0）があること |

- 外れた画像は `REJECTED`（不合格）になり、原本は `rejected/` に残る。
- `--accept-issues` を付けても承認できない。
- 素材IDを付け直して（`classify`）この分類に入れることもできない。
- 素材ごとに規格を変えることはできない。`assets.json` で `weapon_side` の素材に `expect` を書くと、設定の読み込みで止まる。
- 新しい武器を追加するときは、素材ID・分類 `weapon_side`・登録先だけを書く。

## 2. 目視確認（ユーザーが承認時に判断。機械では判定しない）

- 真横からの側面図であること（斜めや俯瞰ではないこと）。
- 銃口が左、ストックが右を向いていること。
- 武器全体が描かれ、部品の欠けや輪郭の欠けがないこと（明るい背景と暗い背景の両方で確認する）。
- 余白と配置のバランス（機械検査で見ているのは、外周が透明であることだけ）。
- レトロFPS向けのピクセルアートの画風であること（太めの暗い輪郭、段階的な陰影）。既存の武器全体図と統一感があること。
- 文字、背景、地面、影など、武器以外のものが描かれていないこと。
- 縦横比を変えていないこと（引き伸ばしや変形がないこと）。

## 3. 登録

- 登録先：weaponlab の作業ツリー（`feature/weapon-balance-lab`）。
  - `AssetPipeline/config/pipeline.json` の `repositories.weapons` で設定している。
  - 書き込めるのは `Assets/Game/Art/Weapons/` の中だけ。
- 素材IDと保存先：

| 素材ID | 保存先 |
| --- | --- |
| `weapon.smg.side` | `Assets/Game/Art/Weapons/SMG/Side/smg_side_design.png` |

- `register <受付ID> --no-commit`：画像を配置するだけで、ステージもコミットもしない。状態は `PLACED_UNCOMMITTED` になる。
- 画像だけをコミットしない。画像・`.meta`・新しいフォルダの `.meta`・参照するファイル（`SkinCatalog.asset` など）・設定するコード・テスト・この仕様書を、1つの単位としてまとめてコミットする。
  - 単位は `AssetPipeline/config/assets.json` の `commit_with` と `referenced_by` で宣言する。
  - `./assetpipe commit-plan <受付ID>` で確認する（読み取りのみ）。
  - ユーザーが手でコミットした後、`register <受付ID>` でそのコミットを記録する（AssetPipeline はコミットしない）。
  - 単位の一部しかコミットされていなければ、登録済みにしない。
- `verify <受付ID>` で、配置したファイル・SHA-256・Git の状態・`.meta` が記録どおりかを確認できる（読み取りのみ）。

## 4. 既存のライフル側面画像（規格外。変更していない）

| ファイル | 寸法 | 描かれている範囲 | 備考 |
| --- | --- | --- | --- |
| `Assets/Game/Art/Weapons/Rifle/Side/rifle_side_design.png` | 1860×846 | 1781×753（周囲に半透明が多い） | 2026-10-21 採用。AssetPipeline を通していない |
| `Assets/Game/Art/Weapons/Rifle/Side/rifle_side_design_opaque.png` | 1860×846 | 1694×553 | スキン用の派生画像（`SkinSetup.RifleSidePath`） |

- 描かれている範囲の幅（1694px）が 1440px を超えている。そのため、切り抜きや透明な余白の追加だけでは、拡大縮小なしに 1440×800 に収められない。
- 対応の候補（どれもユーザーの判断が必要）：
  1. 現状維持（推奨）。ライフルは規格前の採用素材として扱い、AssetPipeline には登録しない。表示側で縦横比を保ったまま縮小して使う（今もそうしている）。
  2. 1440×800 でライフル全体図を描き直してもらい、新しい素材ID（例：`weapon.rifle.side`）として規格どおりに登録する。
  3. 今の画像を縮小（0.85倍以下）して、1440×800 の派生画像を作る。ピクセルアートでは縮小で画素が崩れるので、目視での承認が必要になる。

## 5. 作業単位の完了条件（全武器共通・必須）

武器を1つ追加する作業（ライフル・SMG・ショットガンなど。スキンも同じ）は、次の10項目を1つの作業単位として管理する。
**9と10を省いた場合は、作業単位を完了と判定しない。** 一時的な運用ではなく、今後すべての武器・素材に適用する。

1. 必要な画像をすべて受け取る（`_inbox/<素材ID>/` に保存 → `./assetpipe scan`）。
2. 共通規格（§1）で検査する。
3. ユーザーが画像を正式承認する（`approve` はユーザー自身が実行する。代行しない）。
4. AssetPipeline に正式登録する（`register --no-commit` で配置）。`verify` で記録どおりか確かめる。コミットは、Unity での確認の後に、`commit-plan` で確認した単位をまとめて行う（§3）。
5. Unity に取り込む（`.meta` と GUID、`SkinCatalog.asset` などの参照を確認する）。
6. HUD・装備画面・必要なゲーム画面で表示を確認する。
7. EditMode・PlayMode を検証する。
8. 必要な実機検証を行う。
9. **その武器の `_inbox` の残存ファイルを確認・整理する。**
   - `./assetpipe inbox --asset <素材ID> --save`（読み取りのみ。残っていれば終了コード 1）と、全体の `./assetpipe inbox`。
   - 整理できる候補は、登録・コミット済みの正本と同じ内容のコピーと、OSが作るファイルだけ。
   - ファイルがなくなったら、空の受け渡しフォルダ `_inbox/<素材ID>/` も残さない：`./assetpipe inbox --prune-empty --asset <素材ID>`（確認）→ `--yes`（厳密に空のものだけを rmdir）。
   - 消す前に正本とSHA-256の一致・Unityでの参照を確かめ、作業ごとのバックアップにコピーしてから、1ファイルずつ消す。
10. **残すファイルがある場合は、その理由を記録する**（`docs/PROGRESS.md`、作業のIssueなど）。

- AssetPipeline には自動で削除する機能を作らない。整理はユーザーの指示の範囲で、手で行う。
- 未承認の画像・用途の分からないファイルは消さない。原本のZIPなどは `AssetPipeline/archive/` へ移して保管する。
- 詳しい手順：`AssetPipeline/README.md` 15章。
