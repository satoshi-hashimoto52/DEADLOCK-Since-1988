### 実装済み

| 区分 | 内容 |
| --- | --- |
| テストステージ | 平坦な通路（16m×60m）、床・壁・遮蔽物（木箱、低い壁、柱、ジャンプ用台、ターゲットを隠す壁）。32px程度の低解像度テクスチャ（Pointフィルター、手続き生成） |
| 移動・視点 | CharacterControllerによる移動、ダッシュ（立ちのみ、前進のみ）、ジャンプ（立ち・接地時のみ、押しっぱなしで連続しない、天井に当たると上昇を止めて落下）、重力、ヨー／ピッチ視点 |
| 姿勢 | 立ち／しゃがみ／伏せ（`PostureController`）。移動用カプセルの高さとカメラ高を短い移行時間で補間し、足元は固定（中心＝高さ÷2）。高くなる姿勢へは、移行先の高さのカプセルが収まるかを事前に確認し、塞がっていれば拒否してHUDに「頭上が塞がっています」を表示。空中では姿勢を変えない。しゃがみ・伏せ中のジャンプ入力は立ち上がり要求として消費し、同じ入力でジャンプしない。しゃがみは歩行より遅く、伏せはさらに遅い。状態は `Current`／`IsTransitioning`／`Changed` で参照できる |
| 武器の持ち替え | 銃⇄ナイフ（`WeaponSwitcher`）。持ち替え時間の前半で旧武器を下げ、後半で新武器を上げる。持ち替え中は攻撃不可、ナイフの振り中は持ち替え要求を無視。リロード途中で持ち替えるとリロードを中止（未補充の弾は増えず、銃へ戻しても自動再開しない）。銃を出した直後は引き金を一度離すまで発砲しない |
| 近接攻撃 | 仮のナイフ1種（`MeleeWeapon`／`MeleeDefinition`）。1回の押下で1回、振り始め→命中時間帯→振り終わり。振り中の押下は受け付けない（連打で間隔を縮められない）。命中時間帯に目の位置から前方へ球を掃引し、最初に当たった物で判定を終える（壁なら遮断、1回の攻撃で1対象・重複ダメージなし、自分には当たらない）。遮蔽物の端越しの命中を防ぐため目から対象への視線も確認。弾薬は使わない。立ち・しゃがみ・伏せで使用可。射程・幅・時間帯はSceneビュー（またはGame ViewのGizmos表示）で確認できる |
| デスクトップ入力（開発確認用） | WASD、マウス視点、Shiftダッシュ、Spaceジャンプ、Cしゃがみ、Z伏せ、1銃、2ナイフ、左クリック射撃／近接攻撃、右クリックADS（長押し／切り替えは設定。10.）、Rリロード、Escでカーソル解放、F2でタッチモード切替。キー配置は `DesktopInputSource.Bindings` に集約 |
| タッチ入力 | 左側フローティング仮想スティック、右側ドラッグ視点、FIRE（射撃／近接攻撃）／ADS（長押し／切り替えは設定。10.）／R／JUMP／姿勢（短押し・長押し）／武器切り替えボタン。指ごとにpointerIdを追跡し複数指に対応。ボタン上で始まった指は視点に流れない（FIREボタンのみ、押しながらのドラッグで視点操作可）。ナイフ装備中はADS・Rを無効表示。ダッシュ中はスティックのノブを着色。姿勢・武器ボタンには現在の状態を表示 |
| 二重入力の防止 | `PlayerInputRouter` が1フレームにつき1入力源（タッチ or デスクトップ）だけを採用。モバイル実機では常にタッチ。タッチモード中はUI入力モジュールのバインディングをTouchグループに限定し（物理マウスはUIに届かない）、タッチ部品もマウス由来のポインターを無視 |
| Safe Area | 操作UIとHUDを `SafeAreaFitter`（Screen.safeArea追従）配下に配置。視点ドラッグ領域のみ全画面 |
| 手元武器 | 簡易3Dモデル（基本形状のライフルと手・腕）から腰だめ・ADSを事前レンダリングした2Dスプライト（`WeaponSpriteBaker`）。硬い明暗段階・部品境界の輪郭線・稜線のハイライトと影で、手前の機関部が大きく奥の銃口が小さい遠近を持つ。専用オーバーレイカメラ（ViewModelレイヤー、深度クリア、固定FOV 50°）で描画し、壁際でも埋もれない |
| ADS | 同じモデルを照門の後方から描いたADS画像（フロントサイト先端＝スプライトのピボット＝画面中央＝射撃方向）。腰だめの銃口が中央下へ寄り、ADS画像が下から上がる。切り替えは短いクロスフェード（ADS進行0.45〜0.62）。ワールドカメラのFOVを同時に補間。ADS中は移動・視点感度・拡散・反動が低下 |
| 発砲・リロード表現 | マズルフラッシュ（表示中の銃口位置。ADS時はフロントサイト下）、手前下へ押し戻されて戻るキック（位置・回転・拡大）、小さな歩行ボブ（ADS時はほぼ無し）、リロード時の下げ・傾け（手元を中心に回転、実際のリロード時間に同期）、反動（視点の跳ね上がりと一部自動回復）。表示データは `WeaponViewProfile` |
| 射撃・弾薬 | 発射間隔（フルオート）、装填弾と予備弾の分離、リロード時間、弾切れ時は発砲不可（新たに引き金を引くと自動リロード）、リロード中は発砲不可 |
| 弾道 | 弾ごとに毎フレーム「速度×経過時間」だけ進め、その区間をRaycastで判定（飛翔時間あり・高速弾のすり抜けなし）。最大射程で消滅。トレーサーと着弾痕 |
| ターゲット | 固定ターゲット（ビルボードの2Dスプライト表示と、回転しない当たり判定を分離）。HP、被弾フラッシュ、破壊、3秒後に復活 |
| 弾薬取得 | 手動配置の弾薬箱。取得時は予備弾へ加算（装填弾は変えない）。一度だけ取得 |
| HUD | 照準（拡散に応じて開く、ADS時は非表示）、残弾「装填 / 予備」、RELOADING／RELOAD／NO AMMO表示、リロード進行バー、ヒットマーカー。Editor／PC確認用に、現在の入力モードと操作案内（PC：「Space：ジャンプ」等、未取得時は「Game Viewをクリック」、タッチ：PCキー無効とF2で戻る旨）を左上に表示（C・Z・1・2を含む）。弾数表示と重ならない幅で折り返す。モバイル実機では非表示。弾数の下に現在の姿勢・ダッシュ状態を表示。ナイフ装備中は弾数の代わりに武器名 |
| 開発基盤 | Editorスクリプトによるシーン・仮素材の再生成、iOS Xcodeプロジェクト書き出し、EditMode／PlayModeテスト |

## 2. 検証状況（2026-10-19、基本アクション追加後に再実行）

### Editor（Unity 6000.3.23f1、batchmode）で実行して確認

- プロジェクトのオープン、スクリプトのコンパイル（エラー・警告なし）。
- シーン生成（Editorスクリプト）とPlay Modeでのシーン再生。
- EditModeテスト6件：弾薬の消費が負にならない、途中リロードで残弾を捨てない、リロードで弾が増えない、予備弾加算の上限。
- PlayModeテスト28件（Input Systemのテスト用仮想デバイスで実際の入力経路を使用。2026-10-20に60 fps設定後も全件成功）：
  - 移動、ダッシュ（歩行より速い）、ジャンプと着地、マウス視点。
  - ADSの移行とFOV変化、フルオート射撃と発射間隔、リロード（所要時間・発砲不可・弾数保存）。
  - 弾切れ時に発砲できない、新たな引き金で自動リロード。
  - 弾薬箱が予備弾へ一度だけ加算される（離れて戻っても再加算なし）。
  - 弾が飛翔時間後に命中する、高速弾が2cmの対象をすり抜けない、壁が弾を止める、最大射程で消滅、ターゲット破壊。
  - シーン内で、隠し壁の裏のターゲットに弾が届かず、見えるターゲットには命中する。
  - タッチ：2本指で移動と視点を同時に操作、ボタンから始めたドラッグで視点が回らない、ADSボタンのトグル、タッチモード中はキーボード・マウス入力が作用しない。
  - タッチモード中の物理マウスとの重なり（4通りのタイミング）でも、直後のADS・FIRE（押下中のみ射撃、指を離すと停止）・Rが反応し、マウスでは射撃・移動しない（回帰テスト）。
  - EditorのF2切替：マウスがシミュレーションのタッチとしてボタンに届き、デスクトップ入力として射撃しない。もう一度F2でデスクトップへ戻る。
  - 姿勢：C・Zでカプセル高・中心・目の高さが変わり、足元が上下しない。移動速度が立ち＞しゃがみ＞伏せ。伏せ→しゃがみ、伏せ→立ち。
  - 低い天井：しゃがみ区間で立てない（ジャンプ入力でも立たず跳ばない）、伏せ区間でしゃがみ・立ちへ戻れない、外へ出ると立てる。カメラが天井より下にある。
  - ジャンプ：しゃがみからのSpaceは立ち上がりのみ。立ちでジャンプ、空中のCは無効、押しっぱなしで再ジャンプしない、着地後に再ジャンプ可。ジャンプ台上の天井で頭が止まり、張り付かずに落下・着地する。
  - タッチ姿勢ボタン：短押しでしゃがみ、長押しで押している間に伏せ（離しても短押しは発動しない）、長押しで伏せ→立ち。移動スティックを触り続けたまま操作でき、姿勢ボタンからのドラッグで視点が回らない。
  - タッチのダッシュ：0.85では開始せず0.95で開始、0.8では継続、0.7で解除。横・後退ではダッシュしない。しゃがみ中は深く倒してもダッシュも立ち上がりもしない。
  - 持ち替え：持ち替え中の射撃・近接攻撃なし。ナイフは押下1回で1回、連打で回数が増えない、範囲内の対象へ1回だけ50ダメージ、範囲外は当たらない、弾数不変。
  - ナイフの遮断：薄い壁の向こうの対象に当たらず壁で判定終了、一直線に並んだ2体は手前の1体だけ、伏せでも命中、何もない方向では何も判定しない。
  - リロード中の持ち替え：中止され弾数不変、後で勝手に完了・再開しない。持ち替え中から引き金を押し続けても発砲せず、押し直すと1発。しゃがみ中のリロードは1回だけ完了。
  - タッチの武器ボタン：ナイフでADS・Rが無効になりADSが入らない、FIREでナイフを振る、銃へ戻すと有効に戻る。
  - バックグラウンド移行：FIREとスティックを押したまま一時停止しても、復帰後に押下・射撃・移動が残らず、新しいタッチは効く。
- 1920×1080でのレンダリング画像（腰だめ・ADS・壁際・着弾）を目視確認。ADS時に照準器（フロントサイト先端）が画面中央と一致すること、壁際で手元武器が埋もれないことを確認。
- 基本アクション追加後の画像確認（batchmodeで出力し目視）：しゃがみ区間内の視点、頭上が塞がっている表示、伏せ区間内、伏せでのADS（照準と中央が一致）、持ち替え中（銃が下がる・ナイフが上がる）、ナイフの待機・振り始め・命中の瞬間（ターゲットの被弾表示・ヒットマーカーと同時）、しゃがみ＋ナイフ、iPhone相当2532×1170（ナイフ装備でADS・Rが無効表示）、iPad相当2048×1536（PC案内とタッチボタン）。ボタン・HUDの欠けや重なりがないことを確認。

## 4. 修正履歴

### 2026-10-19 タッチモード中の物理マウスによるタッチ不具合

- 現象（修正前に回帰テストで再現）：タッチモード中に物理マウスのボタン操作とタッチが重なると、次のいずれかが起きた。
  - マウスボタンの解放と同じ入力更新で始まったタッチの押下がUIに届かない（タップが消える）。
  - マウスボタンを押している間に始まったタッチ、またはタッチ中に押したマウスボタンについて、指の解放がUIに届かず、マウスの解放がそのボタンに届く。ボタンが押されたままになり、以後のタップを受け付けない（FIREなら射撃し続け得る）。
  - マウスのクリックとタッチが時間的に離れている場合は発生しない。
- 原因：UI入力モジュール（InputSystemUIInputModule、既定アクション DefaultInputActions）では、マウスとタッチが同じ Point／Click アクションを共有している。両者のボタン状態が重なったり、同じ入力更新で変化したりすると、UI側のポインター処理で取り違えが起きていた。タッチ部品の「マウス由来ポインターを無視する」処理では、届かなかったタッチのイベントを補えなかった。
- 修正：`PlayerInputRouter` がタッチモードの間だけ、UI入力モジュールのアクションに `Touch` バインディンググループのマスクをかける。物理マウスはUIのポインター処理に入らない。デスクトップモードへ戻るとマスクを解除する。Unity・Input Systemのバージョンは変更していない。
- テスト固有設定：なし。テストは製品と同じシーン・同じUI入力設定（既定アクション）を使い、入力デバイスだけをInput Systemのテスト用仮想デバイスに置き換えている。仮想デバイスのイベント順序は再現できるが、iPadOSが実際にマウス／トラックパッドの入力をどう渡すか（タッチとして渡すか等）は検証できない。

  - スライディング：ダッシュ中のCで開始（歩行中のCはしゃがみ）、滑って減速、しゃがみで終わる、押しっぱなし・連打で再発動しない、終了直後は再使用待ち、待ち終了後は再び可能になる。滑走中のSpaceでジャンプしない、射撃できる、壁で止まって終了しすり抜けない。低い天井の下で終わると伏せ、段の端から出ると空中で終了して落下。
  - タッチ：ダッシュ中に姿勢ボタンを押すと即スライディング、押し続けても伏せにならない。
  - 姿勢：しゃがみで低い通路に歩いて入れ、伏せで伏せ区間に入れる（上記の修正）。
- 画像確認（batchmodeで出力して目視）：トレーニング開始画面（iPhone相当2532×1170）、ゾンビの接近・攻撃、被弾時の赤い点滅とHP減少、ゾンビの死亡、失敗画面、メニュー（iPad相当2048×1536）、操作レイアウト編集画面、重なり拒否のメッセージ、クリア画面、しゃがみ区間へのスライディング中の視点。編集画面のツールバーのボタンと文字の重なり、PC用の案内文とメニューボタンの重なりを見つけて修正し、再出力して確認した。

- **人による操作確認はすべて未確認**：ゾンビの手応え・難易度、HPバー・結果画面の見やすさ、レイアウト編集のドラッグ操作感と大きさの刻み、スライディングの速度・距離・操作感、ダッシュ中の姿勢ボタンの押しやすさ。

## 7-2. 仕様照合とスライディングの残課題（2026-10-20）

前回届いていなかったトレーニングの初期仕様を受け取り、実装と照合した。「A・B」は作業指示の項目の区分であり、製品のモード名ではない。トレーニングは基本対人戦モード（デッドライン）とは別の1人用モードとして扱う。D-030・D-031はユーザー承認済み。D-032を「1人用では一時停止、オンラインでは操作入力のみ停止して試合処理は継続、閉じたときに押下状態を持ち越さない」に改めた。

## 9. オンライン試作（LAN・2人、ブランチ `feature/network-prototype`、2026-10-20）

`feature/prototype-foundation` の `4e82f1f` から作成。射撃場・トレーニング（ゾンビ含む）はそのまま残し、オンライン検証用の別シーン `Proto_Online` を追加した。

### 通信方式の選定（検証用、DECISIONS D-033）

| 候補 | 判断 |
| --- | --- |
| Netcode for GameObjects 3.x | Unityの公式パッケージ登録情報で最低 Unity 6000.7 が必要。本プロジェクトの 6000.3 では使えない |
| **Netcode for GameObjects 2.13.3 ＋ Unity Transport 2.7.4** | **採用**。Unity 6.0以上対応（公式マニュアルにiOS対応の記載）、Unity公式、無料、UDPでIP直接指定ができ、ホスト（プレイヤー兼任）＋クライアントの構成がそのまま作れる。クラウド契約・リレー不要 |
| Netcode for Entities など | 今回の規模（2人・LAN・GameObjectベースの既存実装）に対して過大。比較はここまで |

導入前の状態：通信ライブラリは未導入（`com.unity.multiplayer.center` は案内用パッケージのみ）。

iOS：Appleの技術文書 TN3179 で、LAN内のアドレスへのUDP送信・接続にはローカルネットワークの許可が必要、許可の説明文は `NSLocalNetworkUsageDescription` と確認。ビルド後処理でInfo.plistに追加（Bonjour・マルチキャストは使わないので `NSBonjourServices` とマルチキャストのentitlementは不要）。

### 対象外・別課題として記録

- **遅延補償なし**：ホストは「今ホストが知っている相手の位置」で当たりを判定する。通信の遅れの分、撃った側の画面と判定がずれる。
- **不正対策は最低限**：移動・向き・弾の方向はクライアントの申告を採用（速度や壁抜けの検査なし、照準補正の検出なし）。弾数・間隔・生存などの要求の妥当性のみホストで検証。
- **予測の巻き戻しなし**：拒否された射撃も撃った本人の画面には弾が一瞬表示される（ホストからは撃たれていない）。弾数はホストの値で上書きされる。
- ゾンビのネットワーク同期、人数補充用の人型NPC、マッチメイキング、インターネット越しの接続、ホスト移行、途中参加時の試合復元、ランキング・報酬・ガチャ。

## 11. モバイルのADS・射撃操作（2026-10-20、D-035）

| 区分 | 内容 |
| --- | --- |
| 設定 | メニュー → 設定 → 操作設定：①ADS操作方式（長押し／切り替え、タッチ・PC別、既存の保存値を維持）②ADSボタンで照準操作（ON／OFF、タッチ、初期値ON→12-2でOFFに変更）③FIREの動作（通常射撃／ADS連動射撃、タッチ、初期値 通常射撃）。端末に保存（PlayerPrefs）し次回起動時に復元。操作レイアウトは初期化しない。PCの左右クリックの役割は変更なし |

| ADS連動射撃 | FIREを押すとADSを要求し、**銃のADS進行（`AdsBlend`）が1になった時点**から射撃する（ADS移行0.18秒。進行は時間で増えるので、初弾までの時間は描画フレームレートによらず最大1フレームの差）。それまでは射撃入力を出さないので、構えが整う前に離すと撃たない（遅れて撃つことはない）。離すと射撃が止まり、FIREが求めたADSだけが外れる。弾切れ・リロード・持ち替え・死亡などの制限は従来どおり銃が判定。ナイフ装備中は通常の近接攻撃 |
| 解除 | メニュー・配置編集・設定変更・入力モード変更・バックグラウンド・死亡・持ち替えで、射撃（FIREの指）と全入力元のADS要求を解除。押したままの指では射撃もADSも再開しない |
| オンライン | 設定は端末内のみ。相手には実際のADS状態を送る。ADS連動射撃も従来の射撃要求（ホストが生存・装備・弾数・間隔・リロードを検証）を使い、ホスト側の判定は変えていない（ホストはADSを射撃の条件にしていないため、クライアント側で射撃要求を遅らせるだけで整合する） |

検証（Editor、batchmode）：
- EditMode：設定の既定値（長押し・照準ON・通常射撃）、タッチとPCの保存が別、壊れた値は既定へ。
- PlayMode（`TouchAimFireTests` 8件、他）：ADSボタンのドラッグで照準（ON）／照準しない（OFF）、発砲しない。切り替え式でボタン外へ出て戻る・長押ししても1回だけ。長押し式のタッチキャンセルで解除。通常射撃は押してすぐ腰だめで発射。ADS連動はADS移行中は撃たず、移行完了後に撃つ（初弾までADS時間以上）、移行中もFIREの指で照準、離すと停止しADS解除、移行前に離すと後からも撃たない。60fps と 30fps で初弾までの時間の差が1フレーム以内。ADSボタンとFIREのADS要求が互いに解除されない（両方向、切り替え式も）。ナイフではADS連動にならず振る。移動しながら視点＋FIRE、2本の視点指を同時に動かしても1本分だけ回る、最初の指を離すと次の指が飛びなく引き継ぐ、JUMPから始めたドラッグで視点が回らない。メニュー・バックグラウンド・持ち替え・死亡のあと押したままの指で撃たず、ADSにもならない。メニューの設定画面から変更→シーン再読込で復元、保存済みレイアウトは変わらない。
- オンライン（PlayMode）：タッチのADS連動射撃で、構えが整うまで射撃要求が出ない、出た射撃はすべてホストが判定、弾はホストで消費、実際のADS状態（Aiming）が相手へ同期される。
