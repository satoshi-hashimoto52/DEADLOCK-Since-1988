# 実装状況

最終更新：2026-10-19

ゲーム仕様の変更は GAME_SPEC.md／DECISIONS.md で扱う。本書は実装状況・試作条件・課題のみを記録する。

## 1. 基本試作（ブランチ `feature/prototype-foundation`）

目的：モバイルFPSとして基本操作・手元描画・射撃が成立するかの確認。
シーン `Assets/Game/Scenes/Proto_FiringRange.unity` は**射撃練習用の試作シーン**であり、完成したトレーニングモードではない。

### 実装済み

| 区分 | 内容 |
| --- | --- |
| テストステージ | 平坦な通路（16m×60m）、床・壁・遮蔽物（木箱、低い壁、柱、ジャンプ用台、ターゲットを隠す壁）。32px程度の低解像度テクスチャ（Pointフィルター、手続き生成） |
| 移動・視点 | CharacterControllerによる移動、ダッシュ、ジャンプ、重力、ヨー／ピッチ視点 |
| デスクトップ入力（開発確認用） | WASD、マウス視点、Shiftダッシュ、Spaceジャンプ、左クリック射撃、右クリック長押しADS、Rリロード、Escでカーソル解放、F2でタッチモード切替 |
| タッチ入力 | 左側フローティング仮想スティック、右側ドラッグ視点、FIRE／ADS（トグル）／R／JUMPボタン。指ごとにpointerIdを追跡し複数指に対応。ボタン上で始まった指は視点に流れない（FIREボタンのみ、押しながらのドラッグで視点操作可） |
| 二重入力の防止 | `PlayerInputRouter` が1フレームにつき1入力源（タッチ or デスクトップ）だけを採用。モバイル実機では常にタッチ。タッチ部品はマウス由来のポインターを無視 |
| Safe Area | 操作UIとHUDを `SafeAreaFitter`（Screen.safeArea追従）配下に配置。視点ドラッグ領域のみ全画面 |
| 手元武器 | 2D高解像度スプライト（腰だめ用1024×512、ADS用1024×1024の照準器視点）を専用オーバーレイカメラ（ViewModelレイヤー、深度クリア、固定FOV）で描画。壁際でも埋もれない |
| ADS | 腰だめ画像を中央へ寄せつつフェードし、ADS画像が下から上がる。ワールドカメラのFOVを同時に補間。ADS中は移動・視点感度・拡散・反動が低下 |
| 発砲・リロード表現 | マズルフラッシュ、手元のキック、歩行ボブ、リロード時の下げ・傾け、反動（視点の跳ね上がりと一部自動回復） |
| 射撃・弾薬 | 発射間隔（フルオート）、装填弾と予備弾の分離、リロード時間、弾切れ時は発砲不可（新たに引き金を引くと自動リロード）、リロード中は発砲不可 |
| 弾道 | 弾ごとに毎フレーム「速度×経過時間」だけ進め、その区間をRaycastで判定（飛翔時間あり・高速弾のすり抜けなし）。最大射程で消滅。トレーサーと着弾痕 |
| ターゲット | 固定ターゲット（ビルボードの2Dスプライト表示と、回転しない当たり判定を分離）。HP、被弾フラッシュ、破壊、3秒後に復活 |
| 弾薬取得 | 手動配置の弾薬箱。取得時は予備弾へ加算（装填弾は変えない）。一度だけ取得 |
| HUD | 照準（拡散に応じて開く、ADS時は非表示）、残弾「装填 / 予備」、RELOADING／RELOAD／NO AMMO表示、リロード進行バー、ヒットマーカー |
| 開発基盤 | Editorスクリプトによるシーン・仮素材の再生成、iOS Xcodeプロジェクト書き出し、EditMode／PlayModeテスト |

### 責務の分離（将来のオンライン化への備え）

- 入力：`PlayerInputRouter` → `PlayerInputFrame`（デバイス非依存の1フレーム分の意図）
- 戦闘状態：`AmmoState`（Unity非依存）、`GunController`、`ProjectileSystem`、`ShootingTarget`
- 表示：`WeaponViewModel`、`ProjectileVisuals`、`Billboard`、`HudController`（状態を読むだけ）

## 2. 検証状況（2026-10-19）

### Editor（Unity 6000.3.23f1、batchmode）で実行して確認

- プロジェクトのオープン、スクリプトのコンパイル（エラー・警告なし）。
- シーン生成（Editorスクリプト）とPlay Modeでのシーン再生。
- EditModeテスト6件：弾薬の消費が負にならない、途中リロードで残弾を捨てない、リロードで弾が増えない、予備弾加算の上限。
- PlayModeテスト12件（Input Systemのテスト用仮想デバイスで実際の入力経路を使用）：
  - 移動、ダッシュ（歩行より速い）、ジャンプと着地、マウス視点。
  - ADSの移行とFOV変化、フルオート射撃と発射間隔、リロード（所要時間・発砲不可・弾数保存）。
  - 弾切れ時に発砲できない、新たな引き金で自動リロード。
  - 弾薬箱が予備弾へ一度だけ加算される（離れて戻っても再加算なし）。
  - 弾が飛翔時間後に命中する、高速弾が2cmの対象をすり抜けない、壁が弾を止める、最大射程で消滅、ターゲット破壊。
  - シーン内で、隠し壁の裏のターゲットに弾が届かず、見えるターゲットには命中する。
  - タッチ：2本指で移動と視点を同時に操作、ボタンから始めたドラッグで視点が回らない、ADSボタンのトグル、タッチモード中はキーボード・マウス入力が作用しない。
- 1920×1080でのレンダリング画像（腰だめ・ADS・壁際・着弾）を目視確認。ADS時に照準器（フロントサイト先端）が画面中央と一致すること、壁際で手元武器が埋もれないことを確認。

## 3. 既知の課題

- タッチモード中に物理マウスでクリックすると、直後のUIボタンへのタッチが反応しない場合がある（PlayModeテストで観測。Editorのタッチシミュレーションではマウスが無効化されるため発生しない）。iPad＋マウス等の併用は今後の検討事項。
- トレーサーが細く高速なため、静止画では見えにくい。見た目の調整は未実施。
- 仮素材は手続き生成の図形であり、完成版の絵柄ではない。腕・手の描き込み、発砲・リロードのコマアニメーションは未作成。
- 音（発砲音・リロード音・足音）は未実装。
- iOSのバンドルID・会社名はテンプレート／Unityの既定値のまま。署名設定も未変更。
