中心となる体験は、対人戦とモンスター戦を通して生き残り、成績に応じたガチャポイントで武器・スキル・外見を増やすこと。脱出地点からの帰還を主目的とするエキストラクション方式は採用しない。

### 基本ループ

装備・プリセット選択 → マッチング → 開始前の準備 → PvPvE戦闘 → 試合結果 → 条件を満たす場合に報酬獲得 → ガチャ・カスタム解放 → 次の試合。

## 3. モード

### 3.1 TRAINING／トレーニング

- 1人で操作と戦闘を練習するモードを用意する。【確定】
- 敵の種類・数・難易度を調整可能にする案がある。【提案】
- 通常報酬・熟練度を付与せず、未解放カスタムも試せる案がある。【提案】
- オフライン対応の有無は未決定。1人用であることと、オフラインで動作することは区別する。
- 通常マッチのBOT補充とは別モードとして扱う。
- 基本の対人戦モード（デッドライン）とは別の、1人用の練習モードとして扱う。
- 試作の初期仕様（2026-10-20）【試作】：
  - ゾンビ3体。全滅でクリア、プレイヤー死亡で失敗。
  - 討伐数と経過時間を表示する。
  - 再挑戦時にHP・弾薬・敵・弾薬箱・入力状態を初期化する。
  - ガチャポイントや恒久報酬は付与しない。
  - 銃とナイフの両方で敵を倒せる。
  - 敵の攻撃は、当たる瞬間に距離と遮蔽物を再確認する。攻撃の予備動作中に離れれば回避できる。
  - 敵やプレイヤーが死亡した後は、敵の攻撃を停止する。
  - 最後の敵の死亡とプレイヤー死亡が重なっても、結果は一意に決め、結果画面を重複させない。
  - 仮の敵画像はオリジナル素材とし、表示部分をY軸ビルボードにする。
- 初期調整値（製品版の確定値ではない）：プレイヤーHP 100、ゾンビHP 100、ゾンビ攻撃力10、攻撃予備動作0.5秒、攻撃の再使用間隔1.5秒（攻撃開始から次の攻撃開始まで）、ゾンビの移動速度はプレイヤーの通常歩行より遅くする。
- 1人用の射撃場・トレーニングでは、メニューを開いている間ゲームを一時停止する。将来のオンライン対戦では、その端末の操作入力だけを止め、試合・敵・被弾などの処理は継続する。メニューを閉じたとき、押下状態を持ち越さない（D-032）。【確定】

### 3.2 DEADLINE／デッドライン

モード説明案：制限時間まで生き残り、スコア上位を狙え。

- 基本の対人戦モード。ゾンビ・モンスターも存在する。【確定】
- 制限時間終了時の生存者をランキングし、上位に通常ガチャポイントを与える。【確定】
- 試合時間8分、リスポーンなし、生存者優先のスコア順位を試作案とする。【暫定】
- 最後の1人になっても時間終了まで継続する案がある。【提案】
- 生存者0人で終了、死亡後の観戦・退出、通信切断時の復帰猶予は詳細未決定。

#### 通常ガチャポイント

| 生存者内の順位 | 獲得ポイント |
| --- | ---: |
| 1位 | 10 |
| 2位 | 5 |
| 3位 | 3 |
| 4位以下・死亡 | 0 |

上記は合意済みの初期設定。将来のバランス調整は変更履歴に残す。
通常報酬は生存条件を満たす上位者に限定し、死亡時に所持ポイントや所有装備を減らさない。

順位計算にBOTを含めるか、BOT入賞時の繰り上げ、同順位の扱い、途中終了時の順位確定方法は未決定。

## 6. スキル

### パッシブ

装備中に常時有効、または条件成立時に自動発動する能力。1枠。
例：歩行音軽減、リロード短縮、モンスター撃破後の一時的な加速。

### アクティブ

使用タイミングをプレイヤーが選ぶ能力。1枠。
例：一定時間の足音消去、索敵、デコイ。

足音を消す能力などを将来のガチャ要素に含める方針は確定。具体的な効果量・対象音・発動条件は未決定。

「静音歩行」「サイレントステップ」は試作候補名であり、確定した実装対象ではない。アクティブの効果時間＋クールダウン方式も暫定案。使用回数制や使用可能な場面の制限は今後検討する。

武器固有効果とキャラクタースキルは区別する。重複効果の上限・計算順序を別途定義する。

## 7. 武器

### 7.1 近接武器

- サブ武器として装備する。【確定】
- 武器間の性能差は小さくする。【確定】
- 基本は共通性能。差を設ける場合も威力と射程・攻撃範囲の微調整にとどめる。【確定】
- 攻撃速度や移動速度に大きな差を付ける旧提案は採用しない。
- 外見・モーション・効果音で個性を出す方向。
- 銃と近接武器を持ち替えて使う。攻撃ボタンは装備中の武器に応じて射撃／近接攻撃になる。【確定（2026-10-19）】
- 近接攻撃は正面の短い範囲に当たり、壁や遮蔽物の向こうへは当たらない。1回の攻撃で同じ対象へ重複ダメージを与えない。【確定（2026-10-19）】
- 持ち替え時間、威力・射程・攻撃範囲・攻撃間隔、1回の攻撃の対象数（試作は1対象）は試作用の暫定値（PROGRESS.md）。製品版の値は未決定。
- 近接武器の固有効果は、性能差を小さくする方針と矛盾しないかを先に検討する。

### 7.2 銃

銃は近接武器より詳細な性能差を設け、扱い方と交戦距離の違いを楽しめる設計にする。

| 項目 | 内容 |
| --- | --- |
| 基本威力 | 1発の基礎ダメージ |
| 発射速度・方式 | 単発・連射・バーストなど |
| 装弾数 | マガジンに装填できる弾数 |
| リロード時間 | 再装填に必要な時間 |
| 弾薬 | 対応弾薬、予備弾、携行上限、取得量 |
| 有効射程 | 威力を維持できる距離 |
| 威力減衰 | 距離によるダメージ変化 |
| 最大到達距離 | 弾が到達できる限界 |
| 弾速 | 発射から着弾までの時間に影響 |
| 反動・集弾性 | 狙いの変化とばらつき |
| ADS移行時間 | 照準を構えるまでの時間 |

特にリロード・弾薬ドロップ・射程・弾速を作り込む方針は確定。空の状態と途中交換のリロード差、重力・貫通・跳弾・部位倍率などは未決定。

弾速を実際の着弾時間に反映する方向とし、初期企画の「瞬時のRaycast命中」だけで銃全体の完成仕様としない。具体的な飛翔・衝突・ネットワーク遅延補償の実装は別途設計する。

### 7.3 武器固有効果

高レア武器に固有パッシブを付ける構想がある。例：撃破後加速、リロード時の対モンスタースタン、命中した相手の表示時間延長。

現時点では将来構想とする。対象武器、レアリティ、キャラクタースキルとの重複、近接武器への適用は未決定。ミニマップの存在を前提にする効果は、ミニマップ仕様が決まるまで採用しない。

## 8. 弾薬

- エネミー討伐などで弾薬がドロップする。【確定】
- 対応する弾薬を取得すると予備弾へ自動加算する。【確定】
- リロードで予備弾からマガジンへ装填する。【確定】
- 取得しただけで装填中の弾数を直接回復する方式にはしない。
- 拳銃弾・ライフル弾・散弾などの共通カテゴリ方式は提案。
- 途中リロードで残弾を捨てない、試合ごとに規定の支給弾から開始する方針は暫定。
- ドロップ率・取得量・自動取得距離・誰が拾えるか・予備弾上限超過時の扱いは未決定。

例：装填30発／予備60発で弾薬20発を取得すると、装填30発／予備80発になる。数値は説明用。

## 9. 武器種共通カスタム

### 9.1 基本方針

- サプレッサーや弾倉カスタムを、武器種ごとに解放する。【確定】
- 解放済みカスタムは、同じ武器種の対応武器で共通利用する方向。
- カスタム設定は銃・プリセットに紐付ける。
- 解放は永続。付け替え費用なし、試合中変更不可の運用は暫定案。
- 武器種の分類、装着例外、解放方法は未決定。

### 9.2 弾倉枠：2種類から1つ選択

| タイプ | 効果 | 変更しないもの |
| --- | --- | --- |
| 予備弾増加 | 開始時の予備弾数と携行上限を増やす | 1回の装填上限 |
| 装填数増加 | 1回のリロードで装填できる上限を増やす | 予備弾携行上限を増やす効果は付けない |

- 2タイプの存在と、弾倉枠でいずれか1つを選ぶ方式は確定。
- 標準構成を含めた具体的な選択UIは別途設計する。
- 拾った弾薬が自動で予備弾に加算される処理は、どちらでも共通。
- キャラクター装備として別の「予備弾ポーチ枠」を追加する仕様ではない。
- 予備弾増加の例：装填30発／予備上限90発 → 装填30発／予備上限150発。
- 装填数増加の例：装填上限30発 → 40発。
- 上記数値は例。増加量、リロード時間などの代償、装填数増加時の総支給弾数は未決定。

### 9.3 サプレッサー

サプレッサーを武器カスタムに含める方針は確定。
発砲音の到達範囲・マズルフラッシュ・NPCの聴覚検知を抑える案がある。完全無音にはせず、足音スキルとは別に扱う提案。具体的な効果と代償は未決定。

### 9.4 追加カスタム候補

銃口・弾倉・操作系の3枠案、コンペンセイター、ADS用／安定化グリップは未確定。
高速交換マガジンは以前の候補であり、確定した弾倉2タイプに追加しない。
サイト・スコープは将来候補。

### 9.5 解放方法の候補

武器種の使用で熟練度を得て、段階ごとのポイントでカスタムを選択解放する案がある。
敗北時も熟練度を得る案、訓練では得られない案、未解放カスタムを訓練で試せる案は未決定。
この熟練度と、勝利報酬のガチャポイントを混同しない。

## 10. 敵・対戦BOT

| 区分 | 役割 |
| --- | --- |
| ゾンビ・モンスター | PvEの脅威。追跡や攻撃を行う |

## 11. ビジュアルとマップ

### 11.1 元の企画から維持する方針

- Project Warlockを参考にしたレトロ3Dの方向性。
- 壁・床・階段・遮蔽物は3D形状と低解像度テクスチャで構成する。
- 敵・草木・小物には2Dスプライト／ビルボードを活用する。
- 背景は粗いドット感、手元の武器・腕は精細でクッキリした画像にする。
- Pointフィルターを基本候補とする。手元画像1024×1024以上は制作目安であり、全素材の必須規格ではない。
- 最初は平坦なテストステージ。本格マップには階段、高台、キャットウォーク、室内、ドア、森林、霧、市街地などを段階的に検討する。
- 出撃中のマップに保証された安全地帯を設けない。

### 11.2 描画上の検討事項

- 腰だめ・ADS・発砲・リロード用の素材を用意する。
- 腰だめ画像を中央に移動するだけで、照準器を覗く表現が成立すると決めつけない。
- 手元武器の専用描画、背景と手元の解像感の分離を検討する。
- ビルボードの表示と当たり判定を分離し、高低差で見下ろしたときの表示を検証する。
- 他プレイヤー・BOTの外見、向き、構え、装備の見せ方を別途定義する。
- サプレッサーや弾倉の外観差分は、2D手元アニメーションの制作方法と合わせて検証する。

**手元武器のドット絵（2026-10-20、D-041）**：一人称の武器（ライフルの腰だめ・ADS、ナイフと手袋の手、銃口炎）は、**背景より細かく描き込まれ、金属・グローブ・袖の質感をドットの形と陰影で表した2Dピクセルアート**を目標とする。補間なし（Point）で表示し、陰影は少ない色数の段階（固まりの陰影）で表し、ぼかし・グラデーション・ノイズは使わない。暗い背景と明るい背景のどちらでも形が読めるようにする。腰だめとADSは同じ銃に見え、銃口炎は銃口の位置に出し、ADSの照準（フロントサイト）は実際の弾の方向（画面中央）に合わせる。**現在の素材は暫定**：ナイフ・手・銃口炎は手描きの試作、ライフルは3Dベイクを縮小・減色したもので、目標の画風には達していない（完成素材は外部制作で置き換える）。UIアイコンは従来どおり補間あり（Bilinear）のまま。

### 11.3 長時間滞在への対策

元の案は「一定時間留まると背後にゾンビが出現」。
これを確定した出現処理としては扱わず、以下の改善案を検討する。

- 長時間の滞在に応じて周囲の脅威が増す。
- 全プレイヤーから見えない有効な地点で出現する。
- 至近距離や退路を完全に塞ぐ出現を避ける。
- 音で接近を予告し、出現数・間隔に上限を設ける。

**操作アイコン（2026-10-20、D-039）**：攻撃ボタンは銃のとき射撃、ナイフのとき近接のアイコン。ADS・リロード・ジャンプ・持ち替え・メニュー・設定はそれぞれの専用アイコン。**姿勢ボタンのアイコンは「現在の姿勢」を表す**（立ち／しゃがみ／伏せ、スライディング中はスライド）。押したときに何が起きるかではない。ボタンの土台（円形のプレート）と状態表示はUI側で描く：通常（半透明）、押下（明るい黄）、有効（ADS有効など、橙のプレート＋リング＋濃い色のアイコン。実際のADS状態と一致）、使用不可（暗く、アイコンを薄く）。アイコンは表示だけで、タッチの当たり判定はボタン（プレート）のまま。

**モバイルの標準操作（2026-10-20確定、D-037）**：ADSボタン＝覗き込みのON／OFF（切り替え）。ボタンのない右側背景のドラッグ＝視点・照準。FIREを押してドラッグ＝攻撃しながら視点・照準。背景とFIREからの視点操作はADS中も使える。ADSボタンのドラッグでは視点は動かない。新規ユーザー（保存設定なし）の初期値は「ADS操作方式：切り替え」「ADSボタンで照準操作：OFF」「FIREの動作：通常射撃」。ADS長押し・ADSボタンでの照準操作・ADS連動射撃は設定で選べる機能として残す。PCの初期設定と操作（右クリック長押しADS）は変えない。保存済みの操作設定とレイアウトは上書きせず、新しい初期値は保存設定がない項目にだけ適用する。操作設定を初期化した場合（保存値の削除）は新しい標準値になる（レイアウトの初期化とは別）。

ADS・射撃の操作設定（2026-10-20採用、CoD Mobileを参考に「ADSや射撃をする指で照準も動かせる」ことを目的とする）：「メニュー → 設定 → 操作設定」に以下を置く。いずれも端末に保存し、次回起動時に復元する。操作レイアウトは初期化しない。PCの左クリック（射撃）・右クリック（ADS）の役割は変えない。
- ADSボタンで照準操作（モバイル、初期値OFF〔D-037で変更〕）：ONならADSボタンから始めた指のドラッグで視点・照準を動かす（発砲はしない）。OFFならADSボタンはADSの切り替え／保持だけ。
- FIREの動作（モバイル、初期値は従来どおりの通常射撃）：通常射撃は押している間、今の構え（腰だめ／ADS中ならADS）で撃つ。ADS連動射撃は押すとADSへ移り、構えが整ったら（ADS移行が完了したら）撃ち始める。押している指のドラッグで照準を動かせる。構えが整う前に離すと撃たない（後から弾が出ない）。離すと射撃を止め、FIREが求めたADSだけを解除する。ナイフ装備中は従来の近接攻撃。
- 視点：右側の空き領域・FIRE・（設定ONの）ADSから始めた指で視点を動かせる。複数の指が視点を動かせる状態では、先に始めた指を優先し、離したら次の指が今の位置から引き継ぐ（同じ動きの二重加算や急な飛びはない）。姿勢・ジャンプ・リロード等のボタンから始めた指は視点に使わない。ADS中の視点感度は、どこから始めた指でも同じ。
- ADSの要求は入力元ごと（ADSボタン、FIRE）に持ち、どれかが求めている間ADSになる。片方を離しても他方の要求は消えない。
- メニュー・配置編集・設定変更・入力モード変更・バックグラウンド・死亡・持ち替えで、射撃と全入力元のADS要求を解除し、押したままの指では再開しない（押し直しが必要）。

操作ボタンの透過率（2026-10-20採用、D-040）：「メニュー → 設定 → 操作設定 → 操作ボタンの透過率」で0〜100%（1%刻み、数値を表示）。初期値0%（従来の見た目）。対象は攻撃・ADS・リロード・ジャンプ・姿勢・持ち替えボタンと移動スティック。メニューボタン・設定画面・HUD・ロゴは対象外。各部品がもともと持つ不透明度に（1 − 透過率）を掛ける（上書き・重ね掛けはしない）。100%（見えない状態）でも当たり判定と操作は有効で、画面に「100%でも操作は有効」と表示する。変更はすぐ反映され、端末に保存し、再起動・シーン切り替え後も復元する。操作レイアウトの編集中はボタンを100%の濃さで表示し、閉じると保存値に戻す（保存値は変えない）。

ADS操作方式（2026-10-20採用）：「メニュー → 設定 → 操作設定 → ADS操作方式」で「長押し」（押している間だけADS）と「切り替え」（1回押すとON、もう一度でOFF）を選ぶ。初期値は長押し。タッチ用とPC用は別々に端末へ保存し、次回起動時に復元する。切り替え式は押した瞬間に1回だけ切り替わり、押し続けても繰り返さない。長押し式は指をボタンの外へずらしてから離しても解除される。メニュー・配置編集を開く、操作方式・入力モードの変更、バックグラウンドへの移行、死亡、武器の持ち替えでADSは解除され、自動では再開しない（新しく押す必要がある）。ナイフ装備中などADSを使えない間の入力は受け付けず、後で実行する予約も残さない。リロード中のADSは従来どおり可能。オンラインでは操作方式は端末の設定で、相手にはADSしているかどうかだけが伝わる。

操作レイアウトの変更（2026-10-20採用）：ゲーム内の「メニュー → 設定 → 操作レイアウト」で、移動スティック・移動の操作開始領域・FIRE・ADS・リロード・ジャンプ・姿勢・武器切り替えを、実際のゲーム画面に重ねて編集する。ドラッグで移動、選択して大きさを変更し、「適用」「キャンセル」「初期配置に戻す」を選べる。端末に保存し、次回起動時に復元する。位置はSafe Areaに対する相対座標で持ち、回転・解像度変更後も有効にする。Safe Area外への移動、操作できない重なり、メニューボタン（実際のボタン領域と誤操作防止の小さな余白）への配置は受け付けない。Safe Area内であれば左右上部も含めて配置でき（2026-10-20変更、D-038）、FIRE・ADSを上部に置いて人差し指で操作できる。メニューと同じ高さでも左右の空いた場所には置ける。非操作のHUD表示（弾数など）を理由に上端を配置禁止にはしない（重なってもよい）。編集中はゲーム入力を受け付けない。初期配置・大きさの範囲・重なりの許容量は試作用の暫定値。
