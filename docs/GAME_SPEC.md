中心となる体験は、対人戦とモンスター戦を通して生き残り、成績に応じたガチャポイントで武器・スキル・外見を増やすこと。脱出地点からの帰還を主目的とするエキストラクション方式は採用しない。

### 基本ループ

装備・プリセット選択 → マッチング → 開始前の準備 → PvPvE戦闘 → 試合結果 → 条件を満たす場合に報酬獲得 → ガチャ・カスタム解放 → 次の試合。

通常対戦の開始までの工程は「マッチング（最大15秒）→ ロード（最大30秒）→ カウントダウン（5秒）→ 試合（最大5分）」（D-060・D-061）。「開始前の準備（約30秒、D-009）」をこの工程のどこに置くかは未決定（DECISIONS Q-028）。

## 3. モード

### 3.1 TRAINING／トレーニング

- 1人で操作と戦闘を練習するモードを用意する。【確定】
- 敵の種類・数・難易度を調整可能にする案がある。【提案】
- 通常報酬・熟練度を付与せず、未解放カスタムも試せる案がある。【提案】
- オフライン対応の有無は未決定。1人用であることと、オフラインで動作することは区別する。
- 通常マッチのBOT補充とは別モードとして扱う。
- 基本の対人戦モード（デッドライン）とは別の、1人用の練習モードとして扱う。
- 試作の初期仕様（2026-10-20）【試作】：
  - ゾンビ3体。全滅でクリア、プレイヤー死亡で失敗。
  - 討伐数と経過時間を表示する。
  - 再挑戦時にHP・弾薬・敵・弾薬箱・入力状態を初期化する。
  - ガチャポイントや恒久報酬は付与しない。
  - 銃とナイフの両方で敵を倒せる。
  - 敵の攻撃は、当たる瞬間に距離と遮蔽物を再確認する。攻撃の予備動作中に離れれば回避できる。
  - 敵やプレイヤーが死亡した後は、敵の攻撃を停止する。
  - 最後の敵の死亡とプレイヤー死亡が重なっても、結果は一意に決め、結果画面を重複させない。
  - 仮の敵画像はオリジナル素材とし、表示部分をY軸ビルボードにする。
- 初期調整値（製品版の確定値ではない）：プレイヤーHP 100、ゾンビHP 100、ゾンビ攻撃力10、攻撃予備動作0.5秒、攻撃の再使用間隔1.5秒（攻撃開始から次の攻撃開始まで）、ゾンビの移動速度はプレイヤーの通常歩行より遅くする。
- 1人用の射撃場・トレーニングでは、メニューを開いている間ゲームを一時停止する。将来のオンライン対戦では、その端末の操作入力だけを止め、試合・敵・被弾などの処理は継続する。メニューを閉じたとき、押下状態を持ち越さない（D-032）。【確定】

### 3.2 DEADLINE／デッドライン

モード説明案：制限時間まで生き残り、スコア上位を狙え。

- 基本の対人戦モード。ゾンビ・モンスターも存在する。【確定】Stage 30 最終仕様の「通常対戦」はこのモードとして反映した。
- 試合の終わりに全参加枠をランキングし、条件を満たす上位の人間に通常ガチャポイントを与える。【確定】
- リスポーンなし。【暫定】
- 通常対戦の開始条件・終了条件・報酬ルール（8枠・5分・順位報酬）はこのモードだけのもので、射撃場・トレーニング・遺跡などの既存モードには適用しない。【確定（2026-10-31、D-068）】
- 8参加枠は試合内IDで管理し、各枠に人間／NPC・接続・ロード・生死・戦績・報酬資格を持たせる。試合終了の判定と報酬の確定は同じ試合について一度だけ行い、報酬は試合IDと参加枠IDで一意の取引として保存する（§4.7 の保存の仕組み）。試合結果・報酬の確定は将来サーバー側へ移せる責務として分ける。【確定（D-068）】

#### 募集・ロード・開始（D-060）【確定（2026-10-31）】

- **8参加枠固定**。人間プレイヤーの不足はNPCで埋める。人間0人なら無人マッチは開始しない。
- マッチングは最大**15秒**。人間8人が揃えば待機を切り上げて即開始処理。15秒に達したらNPCで8枠にする。
- マッチング画面：人間参加数 `x/8`、残り時間、キャンセルボタン。**確定前だけ**確認なし・ペナルティなしでキャンセルできる。確定後・ロード中・カウントダウン中はキャンセル不可。
- ロード待機は最大**30秒**。画面は自分の実測進捗、準備完了数 `x/8`、残り待機時間。ロード未完了者はNPCに置換し、本人には失敗画面（再マッチング／ホーム）を出す。報酬0pt、元のマッチへは復帰不可。
- 全員の準備完了後、**5秒のカウントダウン**。移動・攻撃不可。カウントダウン中の通信切断は直ちにNPCへ置換し、カウントダウンはリセットしない。
- カウントダウン完了で全員同時に操作を解放し、5分タイマーを開始する。
- 初期配置：有効なスポーン候補から、安全性と参加者間距離を考慮して分散配置する。初期視線・遮蔽物も考慮する。距離などの閾値は調整可能な仮設定（Q-030）。配置できない場合は原因を記録し、無効な位置へ強制的に出現させない。【確定（D-068）】
- ロード進捗は実際の処理状況に基づいて表示し、架空の値を出さない。【確定（D-068）】
- 開始前の準備約30秒（§5、D-009）との関係は未決定（Q-028）。

#### 試合終了と順位（D-061）【確定（2026-10-31）】

- 最大**5分（300秒）**。時間前に生存者が**1人以下**になった時点で即時終了する（最後の生存者がNPCでも同じ）。
- 生存者0人なら全人間プレイヤーが0pt。
- 人間・NPCを含む全8枠に最終順位を付ける。生存者を死亡者より上位にし、各群の中は **キル数の多い順 → 与ダメージの多い順 → 残りHPの多い順 → 被ダメージの少ない順 → 試合内固定IDの小さい順**。
- NPCに対するキル・与ダメージも、人間に対するものと同等に数える。NPC自身の報酬は0pt。
- （旧：試合時間8分【暫定】、最後の1人になっても時間終了まで継続する案【提案】。D-061 で置き換え。）

#### 通常ガチャポイント（D-061、D-018 を置き換え）【確定（2026-10-31）】

| NPC込みの全体順位 | 獲得ポイント |
| --- | ---: |
| 1位 | 10 |
| 2位 | 7 |
| 3位 | 5 |
| 4位 | 3 |
| 5〜8位 | 1 |

- 受け取れるのは、**試合終了時に生存していて、試合から離脱していない人間だけ**。死亡・自主退出・通信切断・ロード除外は常に0pt。
- 同じ試合への二重付与を防ぐ。
- 報酬は確定時に、報酬資格・順位・獲得ポイント・試合ID・参加枠IDを記録してから付与する。付与が完了していない報酬は、アプリ再起動後に検証してから再試行し、二重には付与しない。破損・不正な記録は付与しない。端末の突然の停止や保存領域の障害まで完全な復旧は保証しない。正式オンラインではサーバーが結果と付与を確定する。【確定（2026-10-31、D-069）】
- 死亡時に所持ポイントや所有装備を減らさない。
- 将来のバランス調整は変更履歴に残す。（旧：生存者内の1位10・2位5・3位3pt、4位以下・死亡0pt。DECISIONS §4 に履歴。）

#### 退出・切断・結果画面・再対戦（D-062）【確定（2026-10-31）】

- 試合開始後は、通信切断も自主退出も、同じキャラクターの操作をNPCへ即時移譲する。位置・向き・HP・装備・スキン・装填弾・予備弾・戦績を維持する。元の人間は同じ試合に戻れず、報酬0pt。
- 引き継いだNPCは**同一参加枠**としてキル・与ダメージ等を継続集計する（元の人間への報酬は0pt）。結果画面で引き継ぎを識別表示する。
- 自主退出時は「0pt」「同じ試合へ復帰不可」を明記した確認ダイアログを出し、確定後ホームへ戻る。文言は「退出すると、この試合の獲得ポイントは0ptとなり、同じ試合には復帰できません。」（D-068）。
- 結果画面：全8枠の順位・名前・生死（離脱の識別を含む）・キル数・与ダメージ・残りHP・獲得pt。順位表は試合終了後だけ表示する。
- 操作は「**もう一度対戦**」（新規マッチング。武器・スキン・スキルの編成は維持し、HP・装填弾・予備弾・スキル使用状態・戦績は新しい試合用に初期化）と「**ホームへ戻る**」。

#### 死亡後観戦（D-063）【確定（2026-10-31）】

- 過去状態（位置・向き・視点方向・HP・選択武器・キル数・生死・観戦用の音声イベント）を時刻付きで保持して再現する。現在の状態を10秒前の映像として表示しない。記録が10秒に満たない間は、作った過去を見せずに待機表示にする。保持時間とメモリの上限を管理する。観戦中は戦闘操作を禁止する。【確定（2026-10-31、D-069）】
- 音声は、時刻と位置を持つゲーム内の音声イベントを観戦時刻に再生する方式を優先する（録音した音声全体を遅らせる方式は必須にしない）。正しく再現できない部分は未対応として明示する。【確定（D-069）】
- 死亡直後、**キルカメラなし**で観戦へ移る。蓄積した**10秒前の試合状態**から再生し、待ち時間は原則なし。履歴が足りない最初の10秒間は待機表示。
- 観戦対象は人間・NPCを含む全生存者。対象の一人称カメラの位置・向きに忠実に追従し、観戦者の自由回転・移動は禁止。前／次で対象を選べる。
- 映像とゲーム音（銃声・足音・リロード・環境音など）は**10秒遅延で同期**する。HP・武器・キル数も同じ時点の状態を表示する。残り時間は**現在の試合時刻**を表示する。
- 観戦対象が実際に死亡しても即座には切り替えず、遅延再生の時点で死亡を確認してから自動で切り替える。切り替え先もその遅延時点の生存者。
- HUD：対象の名前・HP・使用武器・キル数・現在の残り時間、前／次、退出。ミニマップ・敵位置・足跡・与ダメージ・試合途中の順位は**表示しない**。戦闘操作は無効。
- 観戦中はいつでも退出できる。確認後ホームへ戻り、死亡者は0pt。試合終了時は遅延再生を中断して結果画面へ。
- **ゲーム内ボイスチャットは実装しない**（ゲーム効果音とは別の話）。
- オンラインでは、観戦用の履歴を専用サーバーが記録し、観戦者には送る時点で10秒以上前のデータだけを送る。死亡した参加者には、生きている体・試合状態の現在のデータを送らない。観戦対象の選択・自動切り替え・不正な要求（存在しない枠・自分の枠・その時点で死亡している枠・現在や未来の時刻）の拒否はサーバーが行う。【確定（2026-11-01、D-073）。記録・送信の頻度と表示の遅れ（約0.1秒の補間分）は試作用の暫定】
- 実装の提案：映像を録画するのではなく、過去の位置・向き・状態と音声イベントの時刻・位置を保持して再現する。iOSのメモリ・通信の検証が必須。正確な10秒同期と情報漏洩の防止を検証する。

## 4. ガチャと永続所有

### 4.2 消費ポイント

| 引き方 | 消費 | 抽選枠 |
| --- | ---: | --- |
| 単発 | 100ポイント | 1枠 |
| 11連 | 1,000ポイント | 11枠。通常枠10＋RARE以上保証枠1（D-055） |

- 「11連＋別途1枠」ではなく、11枠に確定枠を含む。

- 排出確率・レアリティ体系・重複時の扱い・天井は §4.3〜§4.5（D-055〜D-057）。有償ポイント・購入方法は未決定。

通常報酬だけで全て1位の場合、単発には10勝、11連には100勝が必要になる設定。

### 4.3 抽選（D-055）【確定（2026-10-31）】

- 抽選順は **レアリティ → カテゴリ → 個別アイテム**。
- カテゴリの基準比率は武器20%・スキン50%・スキル30%（各レアリティ共通）。
- 同じレアリティ・カテゴリの中の個別アイテムは均等に抽選する。
- 当選したカテゴリに対象が0件なら、そのレアリティに存在するカテゴリだけへ相対比率で再配分する。レアリティ全体で0件なら設定不備として公開・実行を禁止する（無限に再抽選しない）。レアリティを勝手に振り替えない。公開前に、すべてのレアリティ・カテゴリに有効な候補があることを検証する。
- 天井なし。累積抽選回数による確率上昇なし。11連の保証と重複メダル（§4.5）は維持する。

### 4.4 LEGENDARYイベント（D-056）【確定（2026-10-31）】

- LEGENDARYは**指定イベント期間だけ**ガチャ・交換ショップに登場する。通常期間は排出・交換できない。
- 復刻イベント中だけ、過去のLEGENDARYが再登場できる。対象アイテムはイベントごとに指定する。
- イベント終了後も所持・装備・使用できる。交換メダルは失効しない。
- 通常期間の常設ショップは COMMON〜EPIC。ガチャ限定に指定したアイテムはショップから除外する。
- イベント期間は信頼できるサーバー時刻・管理状態を正とする。初期のローカル試験ではシミュレーションし、公開時に端末の時計だけで判定しない。
- イベントガチャでもレアリティ・カテゴリの対象0件を検証する。イベント中にLEGENDARY候補がない場合はLEGENDARYイベントの抽選を公開しない。イベント外のLEGENDARYを混ぜない。
- イベントはイベントID・開始日時・終了日時・対象アイテムIDで管理する。開発用のイベント切り替えは本番用の機能と分ける。【確定（D-067）】

### 4.6 ガチャの画面と履歴（D-058）【確定（2026-10-31）】

- 単発は1件を開封、11連は1件ずつ開封。スキップで全件一覧へ。COMMON〜RAREは標準演出、EPICは強調演出、LEGENDARYは専用演出。全演出をスキップできる。演出の尺・レイアウトは未承認（Q-030）。
- 結果画面は「**もう一度引く**」（同じ単発／11連の新規抽選。確認画面を再度出す）と「**閉じる**」。
- 抽選履歴は**直近100回分**。購入操作1回＝履歴1件で、11連は結果11件を紐付ける。日時・ガチャ形式・全排出・初回／重複・メダルを記録する。古い履歴の削除は資産に影響しない。

### 4.7 保存と移行（D-059）【確定（2026-10-31）】

- 開発・テストはローカル管理。正式オンラインはサーバー権威で管理する（残高・抽選・所持・メダル・履歴）。ローカルのデータを無検証で正式な資産へ移行しない。
- 開発用のエクスポート・インポート機能を用意し、正式運用では無効にする。
- インポートの手順：形式・バージョン・整合性の検証 → ユーザー確認 → 現在データのバックアップ → ガチャ関連データを原子的に完全置換 → 再検証。失敗したら元のデータを保持する／ロールバックする。
- 対応済みの旧スキーマは順に自動移行する。未対応の旧版・未来版・破損データは拒否する。
- 既存の操作レイアウト・武器バランスの実機データなどはインポートの対象にしない。
- ポイント消費・抽選結果・所持品・交換メダル・履歴は一貫した取引として保存し、複数の PlayerPrefs の更新のような部分保存にしない。開発用装備（§13、D-066）で使える武器は正式な所持品として登録しない。【確定（D-067）】
- 実装の具体的な形（保存ファイル・アイテムIDの書式・テスト用アイテムなど）は PROGRESS 12-69（試作用の暫定）。
- 正式オンラインでは、ポイント残高・所持品・交換メダル・抽選と履歴・交換ショップの取引・試合報酬を、試合サーバーと分けたアカウント・経済サービスがサーバーの乱数・時刻で確定し、1つのDBトランザクションで保存する。取引ID（試合報酬は `match:<試合ID>:<参加枠ID>`）は件数で削除せず、同じIDは二度と適用しない。クライアントの残高・報酬・抽選結果の申告は受け付けない。ローカル保存（上記）は開発用・オフライン用に残し、正式の正本にしない。正式なログイン方式は未決定。【確定（2026-11-01、D-072）】具体的な形は PROGRESS 12-74（試作用の暫定）。

## 7. 武器

### 7.1 近接武器

- Slot 3（ナイフ枠）に装備する。【確定】（旧：サブ武器。D-052 で3枠に整理）
- 武器間の性能差は小さくする。【確定】
- 基本は共通性能。差を設ける場合も威力と射程・攻撃範囲の微調整にとどめる。【確定】
- 攻撃速度や移動速度に大きな差を付ける旧提案は採用しない。
- 外見・モーション・効果音で個性を出す方向。
- 銃と近接武器を持ち替えて使う。攻撃ボタンは装備中の武器に応じて射撃／近接攻撃になる。【確定（2026-10-19）】持ち替えの対象は3枠（メイン銃・サブ銃・ナイフ）に拡大した（D-052）。3枠の持ち替え操作は D-065（既存の銃⇄ナイフのボタンに、メイン銃⇄サブ銃の専用ボタンを追加。長押しは使わない。PC はキー1＝メイン銃・2＝ナイフ・3＝サブ銃）。【確定（2026-10-31）】

- 持ち替え時間、威力・射程・攻撃範囲・攻撃間隔、1回の攻撃の対象数（試作は1対象）は試作用の暫定値（PROGRESS.md）。製品版の値は未決定。

| 最大到達距離 | 弾が到達できる限界 |

## 11. ビジュアルとマップ

### 11.1 元の企画から維持する方針

- Project Warlockを参考にしたレトロ3Dの方向性。
- 壁・床・階段・遮蔽物は3D形状と低解像度テクスチャで構成する。
- 敵・草木・小物には2Dスプライト／ビルボードを活用する。
- 背景は粗いドット感、手元の武器・腕は精細でクッキリした画像にする。
- Pointフィルターを基本候補とする。手元画像1024×1024以上は制作目安であり、全素材の必須規格ではない。
- 最初は平坦なテストステージ。本格マップには階段、高台、キャットウォーク、室内、ドア、森林、霧、市街地などを段階的に検討する。
- 出撃中のマップに保証された安全地帯を設けない。

### 11.2 描画上の検討事項

- 腰だめ・ADS・発砲・リロード用の素材を用意する。
- 腰だめ画像を中央に移動するだけで、照準器を覗く表現が成立すると決めつけない。
- 手元武器の専用描画、背景と手元の解像感の分離を検討する。
- ビルボードの表示と当たり判定を分離し、高低差で見下ろしたときの表示を検証する。
- 他プレイヤー・BOTの外見、向き、構え、装備の見せ方を別途定義する。
- サプレッサーや弾倉の外観差分は、2D手元アニメーションの制作方法と合わせて検証する。

**手元武器のドット絵（2026-10-20、D-041）**：一人称の武器（ライフルの腰だめ・ADS、ナイフと手袋の手、銃口炎）は、**背景より細かく描き込まれ、金属・グローブ・袖の質感をドットの形と陰影で表した2Dピクセルアート**を目標とする。補間なし（Point）で表示し、陰影は少ない色数の段階（固まりの陰影）で表し、ぼかし・グラデーション・ノイズは使わない。暗い背景と明るい背景のどちらでも形が読めるようにする。腰だめとADSは同じ銃に見え、銃口炎は銃口の位置に出し、ADSの照準（フロントサイト）は実際の弾の方向（画面中央）に合わせる。**現在の素材は暫定**：ナイフ・手・銃口炎は手描きの試作、ライフルは3Dベイクを縮小・減色したもので、目標の画風には達していない（完成素材は外部制作で置き換える）。UIアイコンは従来どおり補間あり（Bilinear）のまま。

**採用した手元武器（2026-10-20、D-041追記）**：ライフルの腰だめ・ADSは、ユーザーが採用した画像（`Assets/Game/Art/Weapons/Rifle/rifle_hip_approved.png`・`rifle_ads_approved.png`）を使う。ADSはフロントサイトの柱の先端が画面中央（＝実際の弾の方向）に来る。腰だめ→ADSは、腰だめの絵が下へ沈みながらADSの絵が下から上がって入れ替わる。ナイフ・銃口炎は暫定のまま（ナイフの待機・攻撃表示は、2026-10-22に D-044 で採用。下記）。

**武器制作の基準（2026-10-20、D-043）**：今回のライフル（腰だめ・ADS）を、今後の武器の画風・画面上の配置・取り込み手順の基準とする。→ 2026-11-05（D-074）：Stage 38 の新しい武器は、ライフルと同じ配置・動きの値で、1774×887 のキャンバスに描く。腰だめは斜め前から見た3/4の視点で、銃口を画面の中央の奥へ向ける（ゲームは銃身の角度を補正しない）。オンラインの一人称・観戦も、オフラインと同じ画像・配置・反動・リロード・持ち替えの見た目で表示し、表示はサーバーが確定した状態に従う。EPIC SMG の腰だめは、通常版に発光コアと周辺光を重ねる（周辺光を消しても通常版が正しく表示される）。詳細は DECISIONS.md D-043、手順は DEVELOPMENT.md「採用ライフル」と `docs/review/weapon-art-20261020/approved-rifle/README.md`。

**ナイフの攻撃表示（2026-10-22、D-044で採用）**：ナイフは攻撃の進み具合に合わせて、待機 → 振りかぶり（ポーズ1）→ 中央通過（ポーズ2）→ 振り抜き（ポーズ3）→ 待機と画像を切り替える。攻撃判定は従来どおり攻撃フェーズ中に行い、その間は斬撃のポーズ（主にポーズ2）を表示する。攻撃が途中で止まった場合（持ち替え・復活など）は、その場で待機画像に戻る。手・腕スキンは全ポーズに反映する。16:9より狭い画面では、攻撃の軌道全体の横位置を中心0.30へ寄せる（4:3で0.67倍、画像の大きさは変えない）。値は現行の画像・カメラ・表示構成に対する採用値。ポーズ2の袖の継ぎ目は既知の軽微な見た目の課題として許容している。待機画像（`knife_candidate_opaque.png`）も、標準の待機ナイフとして採用済み（D-044追記）。ダメージ・射程・攻撃間隔は変更なし。銃口炎は暫定のまま。

**照準器とADS表示（2026-10-20、D-042、方針）**：照準器を装着していない武器はアイアンサイトのADS表示。拡張装備のドットサイトや倍率付きスコープを装着した場合は、装着した照準器に応じてADS表示と倍率を切り替える。スコープ越しの景色は実際のゲーム空間を表示し、背景込みの固定画像にはしない。対応する照準器は武器ごとに定義する。サイトの装備システム・倍率の切り替え・スナイパーライフルは未実装。

### 11.3 長時間滞在への対策

元の案は「一定時間留まると背後にゾンビが出現」。
これを確定した出現処理としては扱わず、以下の改善案を検討する。

- 長時間の滞在に応じて周囲の脅威が増す。
- 全プレイヤーから見えない有効な地点で出現する。
- 至近距離や退路を完全に塞ぐ出現を避ける。
- 音で接近を予告し、出現数・間隔に上限を設ける。

**操作アイコン（2026-10-20、D-039）**：攻撃ボタンは銃のとき射撃、ナイフのとき近接のアイコン。ADS・リロード・ジャンプ・持ち替え・メニュー・設定はそれぞれの専用アイコン。**姿勢ボタンのアイコンは「現在の姿勢」を表す**（立ち／しゃがみ／伏せ、スライディング中はスライド）。押したときに何が起きるかではない。ボタンの土台（円形のプレート）と状態表示はUI側で描く：通常（半透明）、押下（明るい黄）、有効（ADS有効など、橙のプレート＋リング＋濃い色のアイコン。実際のADS状態と一致）、使用不可（暗く、アイコンを薄く）。アイコンは表示だけで、タッチの当たり判定はボタン（プレート）のまま。

**モバイルの標準操作（2026-10-20確定、D-037）**：ADSボタン＝覗き込みのON／OFF（切り替え）。ボタンのない右側背景のドラッグ＝視点・照準。FIREを押してドラッグ＝攻撃しながら視点・照準。背景とFIREからの視点操作はADS中も使える。ADSボタンのドラッグでは視点は動かない。新規ユーザー（保存設定なし）の初期値は「ADS操作方式：切り替え」「ADSボタンで照準操作：OFF」「FIREの動作：通常射撃」。ADS長押し・ADSボタンでの照準操作・ADS連動射撃は設定で選べる機能として残す。PCの初期設定と操作（右クリック長押しADS）は変えない。保存済みの操作設定とレイアウトは上書きせず、新しい初期値は保存設定がない項目にだけ適用する。操作設定を初期化した場合（保存値の削除）は新しい標準値になる（レイアウトの初期化とは別）。

ADS・射撃の操作設定（2026-10-20採用、CoD Mobileを参考に「ADSや射撃をする指で照準も動かせる」ことを目的とする）：「メニュー → 設定 → 操作設定」に以下を置く。いずれも端末に保存し、次回起動時に復元する。操作レイアウトは初期化しない。PCの左クリック（射撃）・右クリック（ADS）の役割は変えない。
- ADSボタンで照準操作（モバイル、初期値OFF〔D-037で変更〕）：ONならADSボタンから始めた指のドラッグで視点・照準を動かす（発砲はしない）。OFFならADSボタンはADSの切り替え／保持だけ。
- FIREの動作（モバイル、初期値は従来どおりの通常射撃）：通常射撃は押している間、今の構え（腰だめ／ADS中ならADS）で撃つ。ADS連動射撃は押すとADSへ移り、構えが整ったら（ADS移行が完了したら）撃ち始める。押している指のドラッグで照準を動かせる。構えが整う前に離すと撃たない（後から弾が出ない）。離すと射撃を止め、FIREが求めたADSだけを解除する。ナイフ装備中は従来の近接攻撃。
- 視点：右側の空き領域・FIRE・（設定ONの）ADSから始めた指で視点を動かせる。複数の指が視点を動かせる状態では、先に始めた指を優先し、離したら次の指が今の位置から引き継ぐ（同じ動きの二重加算や急な飛びはない）。姿勢・ジャンプ・リロード等のボタンから始めた指は視点に使わない。ADS中の視点感度は、どこから始めた指でも同じ。
- ADSの要求は入力元ごと（ADSボタン、FIRE）に持ち、どれかが求めている間ADSになる。片方を離しても他方の要求は消えない。
- メニュー・配置編集・設定変更・入力モード変更・バックグラウンド・死亡・持ち替えで、射撃と全入力元のADS要求を解除し、押したままの指では再開しない（押し直しが必要）。

操作ボタンの透過率（2026-10-20採用、D-040）：「メニュー → 設定 → 操作設定 → 操作ボタンの透過率」で0〜100%（1%刻み、数値を表示）。初期値0%（従来の見た目）。対象は攻撃・ADS・リロード・ジャンプ・姿勢・持ち替えボタンと移動スティック。メニューボタン・設定画面・HUD・ロゴは対象外。各部品がもともと持つ不透明度に（1 − 透過率）を掛ける（上書き・重ね掛けはしない）。100%（見えない状態）でも当たり判定と操作は有効で、画面に「100%でも操作は有効」と表示する。変更はすぐ反映され、端末に保存し、再起動・シーン切り替え後も復元する。操作レイアウトの編集中はボタンを100%の濃さで表示し、閉じると保存値に戻す（保存値は変えない）。

ADS操作方式（2026-10-20採用）：「メニュー → 設定 → 操作設定 → ADS操作方式」で「長押し」（押している間だけADS）と「切り替え」（1回押すとON、もう一度でOFF）を選ぶ。初期値は長押し。タッチ用とPC用は別々に端末へ保存し、次回起動時に復元する。切り替え式は押した瞬間に1回だけ切り替わり、押し続けても繰り返さない。長押し式は指をボタンの外へずらしてから離しても解除される。メニュー・配置編集を開く、操作方式・入力モードの変更、バックグラウンドへの移行、死亡、武器の持ち替えでADSは解除され、自動では再開しない（新しく押す必要がある）。ナイフ装備中などADSを使えない間の入力は受け付けず、後で実行する予約も残さない。リロード中のADSは従来どおり可能。オンラインでは操作方式は端末の設定で、相手にはADSしているかどうかだけが伝わる。

操作レイアウトの変更（2026-10-20採用）：ゲーム内の「メニュー → 設定 → 操作レイアウト」で、移動スティック・移動の操作開始領域・FIRE・ADS・リロード・ジャンプ・姿勢・武器切り替えを、実際のゲーム画面に重ねて編集する。ドラッグで移動、選択して大きさを変更し、「適用」「キャンセル」「初期配置に戻す」を選べる。端末に保存し、次回起動時に復元する。位置はSafe Areaに対する相対座標で持ち、回転・解像度変更後も有効にする。Safe Area外への移動、操作できない重なり、メニューボタン（実際のボタン領域と誤操作防止の小さな余白）への配置は受け付けない。Safe Area内であれば左右上部も含めて配置でき（2026-10-20変更、D-038）、FIRE・ADSを上部に置いて人差し指で操作できる。メニューと同じ高さでも左右の空いた場所には置ける。非操作のHUD表示（弾数など）を理由に上端を配置禁止にはしない（重なってもよい）。編集中はゲーム入力を受け付けない。初期配置・大きさの範囲・重なりの許容量は試作用の暫定値。

## 13. 技術設計の方向性（実装方式は未確定）

### データ

- ScriptableObjectを武器・スキル等の共通定義に用いる方向。
- 武器定義、所持品、出撃中の残弾や一時効果、永続アカウント情報を分離する。
- 初期企画のWeaponDataクラスは参考であり、そのまま完成形として採用しない。
- スキル・カスタムは安定したIDで識別する方向。
- ガチャ関連データの保存（開発はローカル、正式はサーバー権威、開発用エクスポート・インポート）は §4.7（D-059）。正式オンラインの経済データは、試合サーバーと分けたアカウント・経済サービスが管理する（D-072、ローカル開発の実装は SQLite）。本番のバックエンド構成・ログイン・課金基盤は未決定。
- 開発用の武器装備（D-066）：ガチャ実装前の動作確認のため、開発環境（Editor・開発ビルド）だけで、Slot 1 にメイン武器、Slot 2 にハンドガンを装備でき、Slot 3 のナイフは保つ。装備の制約は通常どおり検証し、不正な組み合わせは拒否する。正式な所持品とは分離し（所持品として保存・付与しない）、正式運用では無効にする。【確定（2026-10-31）】操作の導線・画面は試作用の暫定（PROGRESS 12-68）。

### マルチプレイ

- 入力・表示・ゲーム結果の確定処理を分離する。
- ダメージ、死亡、弾薬消費、敵AI、取得物、勝敗、報酬をサーバー側で確定する方式を候補とする。
- 正式オンラインは**専用サーバー方式**（サーバー権威）。ネットワークライブラリは Netcode for GameObjects 2.13.3・Unity Transport 2.7.4。クライアントは入力と要求だけを送り、位置・HP・弾薬などの自己申告を無条件に信用しない。開発用の接続識別と正式な認証済みの参加資格を分ける。【確定（2026-10-31、D-070）】
- 戦闘（発射・弾薬・リロード・持ち替え・命中・ダメージ・HP・死亡・戦績）と NPC の操作はサーバーが確定する。切断・自主退出は確定と同時に NPC が同じ参加枠を引き継ぐ。射撃の遅延補償は、サーバー時刻の履歴から射撃者が見ていた時刻の状態を復元して判定する方式（上限と拒否の条件あり）。【確定（2026-11-01、D-071）。上限時間・NPC の反応時間や命中率などの数値は試作用の暫定】
- 接続：参加が承認される前の失敗（応答がない・通信層の切断）だけを、最初の接続を含めて計3回まで自動で再試行する。サーバーの拒否と、参加が承認された後の切断は再試行しない。試合確定後の同じ試合への復帰は認めない（切断した枠は NPC が引き継ぐ）。【確定（2026-11-01、D-073）。打ち切りの12秒は試作用の暫定】
- インターネット上のマッチング、外部ホスティング、正式な認証は未決定。
- ローカルセーブのみで本番のガチャポイント・課金所有情報を管理する設計は、別途判断が必要。
- 1人操作の試作後、早期に2人接続を検証する案がある。

### ロード診断（D-064）【確定（2026-10-31）】

- 端末内の専用領域に診断ログを保存する。**直近100件・30日**の両方の上限で、古いものから自動削除する。
- 開発中はロードの成功・失敗・タイムアウトをすべて記録する。正式運用は失敗・タイムアウト中心。
- 記録：日時、結果／エラー種別、連続失敗回数、**ロード全体の時間と段階別の時間**（シーン読み込み・アセット初期化・通信同期・参加準備など、実測できる段階）。並列処理の合計を全体時間として扱わない。計測していない段階は未計測と書く。
- ロード全体が**10秒を超えたら** `SLOW_LOAD` を付ける。プレイヤーへの特別な警告は出さず、ロードを続ける。30秒のタイムアウトとは別。
- オンラインでは、段階を「シーン読み込み・アセット初期化・通信接続と同期・参加準備」とし、通信の時間は実際の開始・終了で測る。マッチング待ち（参加の承認から試合の確定まで）はロードの時間に含めない。30秒のタイムアウトは試合の確定から数える。【確定（2026-11-01、D-073）】
- **3回連続でロードに失敗したら**警告を強める。再マッチングの回数は制限しない。正常に試合へ参加したら失敗回数をリセットする。
- 開発メニューから**構造化JSON**で書き出し、**iOSの共有シート**（AirDrop・ファイル保存など）を使う。元のログは保持する。書き出したファイルは端末内のローリング削除の対象外。
- 秘密情報をログに含めない。正式運用では開発用の書き出しを無効にする。
- 段階ごとに開始・終了・経過時間を記録し、未実行・未対応の段階はその旨を記録する（架空の時間を記録しない）。10秒超過だけを理由にロードを中断しない。開発版は成功・失敗・タイムアウトを記録し、リリース版は通常の成功ログを抑制する。ガチャ・武器調整ラボ・PlayerPrefs とは独立して保存する。個人情報・認証情報・秘密鍵・アクセストークンを記録しない。3回連続の失敗では端末・通信環境の確認を促す。【確定（2026-10-31、D-069）】
- オンライン対戦のメニュー・設定画面は端末ローカルの操作入力を止めるだけとし、試合・敵・被弾などの処理は継続する。ゲーム全体の一時停止は1人用の射撃場・トレーニングに限る（D-032）。
- PvPvE検証（2026-10-20）【試作の検証ルール。デッドライン・イベントの勝敗仕様としては確定しない】：オンライン検証で2人がそろったら、ホストの開始操作でゾンビ3体（トレーニングと同じ調整値）と共有の弾薬箱2個を出す。戦闘中は参加枠を閉じる（途中参加の状態復元は対象外）。プレイヤー同士の攻撃も有効。ゾンビ全滅、または生存プレイヤー0人で終了し、同じフレームで両方成立したら生存0人を優先。結果（ゾンビ残数・各プレイヤーの生死）はホストが一度だけ決める。ランキング・ガチャポイント・恒久報酬なし。戦闘中は対人検証用の自由リスポーンを使えず、ホストの再開始でプレイヤー・敵・弾薬・弾薬箱を初期化する。ゾンビの生成・移動・対象選択・攻撃・HP・死亡はホストが処理する。
- LAN 2人の接続試作（2026-10-20）：検証用の方式（D-033）。ホストがHP・弾薬・発射間隔・ダメージ・死亡を確定し、クライアントから命中やダメージ量は送らない。移動はクライアント側の位置を採用（試作の割り切り）。ゾンビの同期・人数補充BOT・マッチメイキング・インターネット越しの接続・ホスト移行・途中参加の復元は対象外。【試作】
