# DEADLOCK: Since 1988 — Stage 30 最終仕様書

- 状態: **対話で確定した設計仕様**。Unity実装済みを意味しない。
- 対象: iOS横画面 / Unity 6 URP 3D / 通常対戦・武器拡張・ガチャ・観戦・マッチング・診断。
- 原則: 「確定」「仮値」「未決定」を混同しない。現行コードと衝突する場合は勝手に改変せず差分を報告。

## 1. 武器・ロードアウト

### 1.1 装備枠【確定】
- Slot 1: プライマリ。Rifle、通常SMG、Shotgun、LMG、EPIC SMG。Handgunは禁止。
- Slot 2: セカンダリ。Handgunと、将来明示的に許可したセカンダリ武器のみ。Rifle/SMG/Shotgun/LMG/EPIC SMGは禁止。
- Slot 3: ナイフ。
- 武器ごとに装填弾・予備弾・リロードを分離し、切替所要時間・移動速度補正・移動中の精度補正を持たせる【確定】。具体的な倍率・秒数は未決定。
- 既存Rifleの操作感・設定を不意に変えないこと。

### 1.2 武器性能【確定と仮案】
| 武器 | ダメージ | 発射レート | 装弾数 | 備考 |
|---|---:|---:|---:|---|
| Rifle | 25（現行値） | 600RPM（現行値） | 30（現行値） | 基準値。実コードと照合 |
| 通常SMG | **17【確定】** | **900RPM【確定】** | **35【確定】** | Slot 1 |
| Shotgun | 12/ペレット【仮値】 | 0.9秒/射【仮値】 | 6【仮値】 | **1射8ペレット【確定】、フルマガジン一括リロード【確定】** |
| Handgun | 30【仮値】 | 半自動・最大400RPM【仮値】 | 12【仮値】 | **Slot 2のみ【確定】** |
| LMG | 24【仮値】 | 700RPM【仮値】 | 75【仮値】 | Slot 1 |
| EPIC SMG | 18【仮値】 | **950RPM【確定】** | **28【確定】** | EPIC、Slot 1、高連射・低装弾型 |

仮称（**未承認**）: `SG-12 Tactical`、`HG-9 Compact`、`LMG-75 Support`、`XSMG-88 Prototype`。命名方針は「1980年代軍用風の型番」【確定】。

### 1.3 弾薬【確定】
- 弾薬タイプを導入する。ただし**予備弾倉は武器インスタンスごとに独立**し、同じ弾種でも共有しない。
- 開始時: 装填弾は満タン、予備弾は各武器の**2マガジン分**。
- 予備弾の上限: 各武器**3マガジン分**。
- 弾薬箱1つ: **装備中の各銃へそれぞれ1マガジン分**を予備弾に補充（上限適用）。ナイフ対象外。
- 例: Rifle装填30/予備60/上限90、通常SMG装填35/予備70/上限105、EPIC SMG装填28/予備56/上限84。
- Shotgun 6/12/18、Handgun 12/24/36、LMG 75/150/225 は装弾数自体が仮値のため連動する仮値。

### 1.4 画像素材【制作方針】
- 各新武器は最低3種類: 側面シルエット、腰だめ視点、ADS視点。4武器で12画像を初期目標。
- 側面素材は1440×800 RGBA8・外周透明など既存AssetPipeline仕様に従う。FPS視点素材は別途仕様と照合。
- 外部の別チャットで画像制作・ユーザー承認後、AssetPipeline経由で登録。未承認画像の自動採用は禁止。
- `_inbox`は作業単位完了後に空、不要な空フォルダは整理。

## 2. ガチャ経済・抽選【確定】

### 2.1 消費・排出対象
- 単発: **100pt**。11連: **1,000pt**、通常枠10 + RARE以上保証枠1。
- カテゴリ: 武器20%、スキン50%、スキル30%（各レアリティ共通の基準比率）。
- 抽選順: **レアリティ → カテゴリ → 個別アイテム**。
- 同一レアリティ・カテゴリ内の個別アイテムは**均等抽選**。当選カテゴリ内に対象0件なら、そのレアリティの存在するカテゴリだけへ相対比率で再配分。レアリティ全体で0件なら設定不備として公開・実行を禁止（無限再抽選しない）。
- 天井なし。累積抽選回数による確率上昇なし。11連保証と重複交換メダルは維持。

### 2.2 排出率
| レアリティ | 通常期間・単発/11連通常枠 | LEGENDARYイベント期間・通常枠 | 通常期間・11連確定枠 | イベント期間・11連確定枠 |
|---|---:|---:|---:|---:|
| COMMON | 60/99.5 = **60.3015075…%** | 60% | 0% | 0% |
| UNCOMMON | 25/99.5 = **25.1256281…%** | 25% | 0% | 0% |
| RARE | 12/99.5 = **12.0603015…%** | 12% | 12/14.5 = **82.7586207…%** | 12/15 = **80%** |
| EPIC | 2.5/99.5 = **2.5125628…%** | 2.5% | 2.5/14.5 = **17.2413793…%** | 2.5/15 = **16.6666667…%** |
| LEGENDARY | **0%** | **0.5%** | **0%** | 0.5/15 = **3.3333333…%** |

内部計算は元の重み `60:25:12:2.5:0.5` を使い、イベント有無に応じて適格対象を除外して正規化する。表示上の丸め値は抽選に使わない。RARE以上保証枠は対象重み `12:2.5[:0.5]` を使用する。

### 2.3 LEGENDARYイベント【確定】
- LEGENDARYは**指定イベント期間だけ**ガチャ・交換ショップに登場。通常期間は排出・交換不可。
- 復刻イベント中のみ過去LEGENDARYが再登場可能。対象アイテムはイベントごとに指定。
- イベント終了後も所持・装備・使用は可能。交換メダルは失効しない。
- 通常期間の常設ショップはCOMMON〜EPIC。ガチャ限定指定アイテムはショップから除外。
- イベント期間は信頼できるサーバー時刻・管理状態を正とする設計（初期ローカル試験ではシミュレーションし、公開時に端末時計だけで判定しない）。
- イベントガチャでもレアリティ・カテゴリの対象ゼロ件検証が必要。イベント外のLEGENDARYを混入させない。

### 2.4 重複・交換ショップ【確定】
| レアリティ | 重複時メダル | 交換メダル価格 |
|---|---:|---:|
| COMMON | 1 | 30 |
| UNCOMMON | 3 | 100 |
| RARE | 10 | 350 |
| EPIC | 30 | 1,000 |
| LEGENDARY | 100 | 3,500（対象イベント中のみ） |

- 未所持時はアイテム取得。所持済みなら上記メダルへ自動変換。抽選確率は所持状況に依存しない。
- 武器・スキン・スキルすべて同価格表。所持済みアイテムを重複交換できない。
- 個別の「ガチャ限定」フラグで交換不可にできる。**EPIC SMGはガチャ・ショップ双方で入手可能**。
- ガチャポイントと交換メダルは独立通貨。

### 2.5 画面・ガチャ履歴【確定】
- 単発・11連とも、**全ガチャ購入前に消費pt、現在残高、購入後残高の確認画面**を表示。
- 抽選/消費/付与は一体として確定・保存後に演出を開始し、二重タップやアプリ中断で重複・喪失しない。
- 単発は1件開封、11連は1件ずつ開封。**スキップで即全件一覧**。通常COMMON〜RAREは標準演出、EPICは強調、LEGENDARYは専用演出。全演出スキップ可。
- 結果画面は「**もう一度引く**」「**閉じる**」。前者は同じ単発/11連の**新規抽選**で、再度ポイント確認必須。
- 抽選履歴: **直近100回分**。単発・11連とも「購入操作1回=履歴1件」で11連は結果11件を紐付け。日時、ガチャ形式、全排出、初回/重複、メダルを記録。古い履歴の削除は資産に影響しない。

### 2.6 保存・移行【確定】
- 開発・テスト: ローカル管理。正式オンライン: サーバー権威管理（残高、抽選、所持、メダル、履歴）。ローカルデータを無検証で正式資産へ移行しない。
- 開発用エクスポート・インポート機能を提供し、正式運用では無効化。
- インポートは**形式/バージョン/整合性検証 → ユーザー確認 → 現在データのバックアップ → ガチャ関連データを原子的に完全置換 → 再検証**。失敗時は元を保持/ロールバック。
- 対応済み旧スキーマは順次自動移行。未対応旧版・未来版・破損は拒否。
- 既存の操作レイアウト・武器バランス実機データ等をインポート対象にしない。

## 3. 通常対戦・報酬【確定】

### 3.1 募集・ロード・開始
- 通常対戦: **8参加枠固定**。人間プレイヤー不足はNPCで埋める。人間0なら無人マッチは開始しない。
- マッチング最大**15秒**。人間8人が揃えば待機を切り上げ即開始処理。15秒到達時はNPCで8枠にする。
- マッチング画面: 人間参加数 `x/8`、残り時間、キャンセルボタン。**確定前のみ確認・ペナルティなしでキャンセル可**。確定後・ロード中・カウントダウン中はキャンセル不可。
- ロード待機最大**30秒**。画面は自己の実測進捗、準備完了数 `x/8`、残り待機時間。ロード未完了者はNPC置換、本人へ失敗画面（再マッチング/ホーム）、報酬0pt、元マッチへの復帰不可。
- 全員の準備完了後、**5秒カウントダウン**。移動・攻撃不可。カウントダウン中の通信切断は直ちにNPCへ置換し、カウントダウンはリセットしない。
- カウントダウン完了で全員同時に操作解放、5分タイマー開始。
- マップ初期配置: **有効なスポーン候補から安全性と参加者間距離を考慮した分散配置**。初期視線・遮蔽物を考慮。距離などの閾値は調整可能な仮設定。

### 3.2 試合終了
- 最大**5分（300秒）**、あるいは時間前に生存者が**1人以下**になった時点で即時終了。
- 生存者0なら全人間プレイヤー0pt。生存者1なら終了。最後がNPCでも同じ。
- 人間・NPCを含む全8枠に最終順位を付与。生存者を死亡者より上位にし、各群内では **キル数降順 → 与ダメージ降順 → 残りHP降順 → 被ダメージ昇順 → 試合内固定ID昇順**。退場/NPC引継ぎ枠の具体的な表示は下記。
- NPCに対するキル/与ダメージも人間に対するものと**同等**に加算。NPCの自身への報酬は0pt。
- 報酬順位はNPC込みの全体順位で計算。**試合終了時に生存しており、試合から離脱していない人間のみ**受給。
- 報酬: 1位10pt、2位7pt、3位5pt、4位3pt、5〜8位1pt。死亡・自主退出・通信切断・ロード除外は常に0pt。同一試合への二重付与を防ぐ。
- 退出・通信切断後のNPC引き継ぎキャラクターは**同一参加枠**としてキル・与ダメージ等を継続集計するが、元人間への報酬は0pt。結果画面に引き継ぎを識別表示。

### 3.3 試合中の退出・切断と再対戦
- 試合開始後、**通信切断も自主退出も**同じキャラクターの操作をNPCに即時移譲。位置・向き・HP・装備・スキン・装填弾・予備弾・戦績を維持。元の人間は同じ試合へ復帰不可・報酬0pt。
- 自主退出時は「0pt」「同じ試合へ復帰不可」を明記した確認ダイアログ。確定後ホームへ戻る。
- 結果画面: 順位、名前、生死（離脱識別含む）、キル数、与ダメージ、残りHP、獲得pt。全8枠表示。順位表は試合終了後のみ。
- 操作は「**もう一度対戦**」「**ホームへ戻る**」。再対戦は新規マッチング。同じ武器・スキン・スキルの**編成は維持**するがHP、装填・予備弾、スキル使用状態、試合戦績は新規試合用に初期化。

## 4. 死亡後観戦【確定】
- 死亡直後、**キルカメラなし**で即時観戦へ。蓄積された**10秒前の試合状態**から再生し、待ち時間は原則なし。履歴が不足する最初の10秒間は待機表示。
- 観戦対象は**人間・NPCを含む全生存者**。対象の一人称カメラ位置・方向を忠実に追従し、観戦者の自由回転・移動は禁止。前/次の対象選択可。
- 映像とゲーム音（銃声・足音・リロード・環境音等）は**10秒遅延で同期**。HP・武器・キル数も同時点の状態で表示。残り時間は**現在の試合時刻**を表示。
- 観戦対象が実際に死亡しても即切替せず、**10秒遅延の再生時点で死亡を確認してから**自動切替。切替先もその遅延時点の生存者。
- HUD: 対象の名前・HP・使用武器・キル数・現在残り時間、前/次、退出。ミニマップ、敵位置、足跡、与ダメージ、試合途中順位は**表示しない**。戦闘操作無効。
- 観戦中いつでも退出可。確認後ホームへ戻り、死亡者は0pt。試合終了時は遅延再生を中断し結果画面へ。
- **ゲーム内ボイスチャット自体を実装しない**。ゲーム効果音とは独立。
- 実装提案: 映像録画を保持するのではなく、過去の位置/向き/状態と音声イベント時刻・位置を保持して再現。iOSのメモリ/通信検証必須。正確な10秒同期・情報漏洩防止を検証する。

## 5. ロード診断【確定】
- 端末内の専用領域へ診断ログを保存。**直近100件・30日**の両上限を適用して古いものから自動削除。
- 開発中はロード**成功・失敗・タイムアウトすべて**記録。正式運用は失敗/タイムアウト中心。
- 記録: 日時、結果/エラー種別、連続失敗回数、**ロード全体時間および段階別時間**（シーン読み込み、アセット初期化、通信同期、参加準備等の実測可能な段階）。並列処理の合計を全体時間として扱わない。未計測は未計測と記載。
- **ロード全体が10秒を超えた場合** `SLOW_LOAD` を診断ログに付与。プレイヤーへの特別な警告は表示せずロード継続。30秒タイムアウトとは独立。
- **3回連続ロード失敗**で警告を強化するが、再マッチング回数は制限しない。正常な試合参加時に失敗カウントをリセット。
- 開発メニューから**構造化JSON**で書き出し、**iOS共有シート**でAirDrop・ファイル保存などを利用。元ログを保持。書き出し済みファイルは端末内ローリング削除の対象外。
- 秘密情報をログへ含めない。正式運用では開発用書き出しを無効化。

## 6. 未決定事項と実装時の扱い
- **仮値**: Shotgun/Handgun/LMGのダメージ・レート・装弾数・リロード秒数、EPIC SMGダメージ、武器ごとの反動/精度/移動補正/射程、射程減衰、個別切替速度。実コード調査とPlaytest後に調整。
- **未承認**: 武器モデル名候補、具体的な銃声/ビジュアル、FPS武器素材の最終規格、ガチャや観戦の具体的な演出尺/レイアウト。
- **実装上の設計選択**: 参加枠の一意ID、同時死亡、スポーン不能/一部NPC初期化失敗、遅延履歴欠落/対象なし、ロード失敗とNPC置換の厳密な競合、サーバーのトランザクションと権限境界。
- **ロジック上の整合性**: すべてのレアリティ・カテゴリで有効抽選候補が存在するよう、公開前にガチャテーブルを検証する。イベント中にLEGENDARY候補がない場合はLEGENDARYイベント抽選を公開しない。レアリティを勝手に振り替えない。
- **公式の初期設定案としてのみ**開発者が可変値を設定できるが、「ユーザー正式承認値」と混同しない。

## 7. 受入条件
1. 全確定仕様と異なる既存コードを明確に把握し、段階別の修正方針を作る。
2. 抽選率の数学的検証（通常/イベント、単発/11連、対象ゼロ件）、重複、メダル、ポイント、イベント境界、データ復旧を自動テスト。
3. 順位/生死/離脱/NPC引継ぎ/0pt/重複付与防止、8人固定、15秒募集、30秒ロード、5秒開始、5分上限、早期終了を自動テスト。
4. 観戦の時刻整合性・音声同期・視点切替・情報非表示・退出をテスト。
5. iPhone横画面（16:9系）とiPad（4:3）のSafe Area、操作を実機検証。
6. 既存Unity機能、ローカル個人設定/調整データ、AssetPipeline、Git未コミット変更を保全。
